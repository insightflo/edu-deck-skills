리소스팩 — 설계 8종 × 학습 흐름 8종

눈에 보이는 다양함은 설계가 만든다 — 워크북의 마주본 면, 사례철의 기록A/B, 잡지의 편집 지면처럼 배치 문법 자체가 다르다. 흐름은 수업의 뼈대(단계 구성·문안)를 바꾼다. 8×8=64조합을 전수 빌드·검사했다(64/64 PASS).

같은 주제·같은 casebook 설계로 흐름만 바꿔 실제로 조립한 덱 8개다 — 흐름은 단계 수·순서·문안(수업의 뼈대)을 바꾼다. 카드를 누르면 크게 볼 수 있다.

모션 시그니처 — 42종 전체 + 공통 기법 5종

공통 기법 5종 — 실행 이름 위에 얹히는 조형 어휘 (data-fx)

계열 시그니처와 별개로 조각이 data-fx 로 옵트인하는 기법이다. 인쇄·정적 상태는 기법 없을 때와 픽셀 차이 0(검증 완료).

아키텍처 모션 그래픽 키트 — 생성기 3종 + 실행 이름 1종

시맨틱 JSON(nodes·edges·zones·states)을 scripts/arch_layout.mjs가 빌드 시점 dagre 배치로 svg.dg 조각으로 굽는다 — 런타임 레이아웃 엔진 없이 고정 좌표. 전 장 같은 계열 arch-diagram이라 한 실행 이름 arch-trace(등장+선 그리기+패킷)가 발화한다. 두 덱 전부 regen --check로 결정적 재생성된다(모델만 저장소 안에 완결). 아래 6장은 원형 키트, 이어지는 SI 실무형 10유형 11장은 확장 문법 — 호출/응답 화살촉쌍(실선 블록↔점선 오픈촉)·소속존 면색≠신뢰경계 점선·존 사이 경계선·보조 연결(aux) 정적선·arch_lanes.mjs 레인 레이아웃(빌드 시점 토큰 시뮬레이터 — 반려 재신청 재방문까지 data-step/data-lit만으로 재생, 엔진 무변경). 카드에 스크롤하면 실물로 움직이고, 누르면 크게 본다.
