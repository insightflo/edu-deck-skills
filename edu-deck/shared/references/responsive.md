# 화면 크기별 보기

교육 내용·단계·노트·퀴즈 상태는 하나입니다. 화면 크기에 따라 배치만 바뀝니다. 기존 HTML에는 자동 반영되지 않으므로 원본 `src/`에서 다시 조립해야 합니다.

## 화면 계약

- **1200px 이상:** 기존 1920×1080 발표 무대를 화면에 맞춰 표시합니다. 데스크톱 키보드·클릭 이동을 유지합니다.
- **1199px 이하:** 모든 장이 원래 1920×1080 배치 그대로 min(화면 폭÷1920, 사용 높이÷1080) 배율로 축소되어 하나의 세로 스크롤로 이어집니다(사용 높이 = 위쪽 막대 아래~아래 탐색줄 위 사이의 실측 띈 높이 − 간격). 재배치·글꼴 하한·도식 글자 목록은 없습니다 — 배치가 뜻을 전하므로 바꾸지 않습니다. 각 장의 단계는 스크롤이 지나며 자동으로 열리고, 한 번 열린 단계는 위로 돌아가도 닫히지 않습니다. 현재 장은 화면에 가장 넓게 보이는 장이며 번호·진행·노트·자습·주소 해시가 그 장을 따라갑니다. 작은 글자는 장 본문을 눌러 여는 줌 뷰어로 읽습니다 — 현재 공개 단계 그대로의 장을 화면에 맞춰 보여 주며, 두 번 탭·핀치로 확대하고 ‹ › 버튼으로 이웃 장을 봅니다(버튼·퀴즈·탭·코드·핀 같은 조작 요소 위의 탭은 열지 않습니다). 세로 폰에서는 "가로로 돌리면 더 크게 보입니다" 안내가 세션당 한 번 뜹니다. 가로 휴대폰(844×390 등)은 장 하나가 화면 높이에 맞춰 통째로 보이고, 좁아진 폭은 가로 가운데에 놓입니다.
- **맞춘 한 장 보기:** 1199px 이하여도 가로 방향이고 폭 960px·높이 540px 이상이면(태블릿 가로 등) 1920 무대를 화면 크기에 맞춘 한 장으로 보여 줍니다. 무대는 아래 탐색줄을 비켜 맞추고 스와이프·탐색줄로 넘깁니다. 주소 끝 `?view=slide`(맞춘 한 장)·`?view=scroll`(세로 읽기)로 보기를 강제할 수 있습니다.
- **모바일 조작:** 화면 아래 44px 이상 버튼으로 이전·다음·검색·설명·노트·용어집·인쇄·전체화면·처음/목차를 엽니다. 화면 높이가 500px 이하면 탐색줄은 한 줄로 모이고 필요하면 가로로 밀어 쓰며, 위쪽 막대의 목차·검색 버튼은 숨겨 한 벌만 보입니다. 세로 읽기에서 스크롤 자체가 읽기 동작이므로 이전·다음·화살표 키는 단계가 아니라 장 단위로 이동하고, 검색·목차 선택도 해당 장 머리로 스크롤합니다. 장 본문 탭은 넘김이 아니라 줌 뷰어를 엽니다. 맞춘 한 장 보기에서는 스와이프·단계 넘김을 유지합니다. 전체화면은 브라우저가 지원할 때 동작합니다.
- **도식:** HTML·SVG 도식 모두 장의 일부로 원래 위치·크기 그대로 축소됩니다. 별도의 글자 목록·읽기창은 두지 않습니다. 답안 테두리에 붙는 채점 표시(`.ed-mark`)도 장과 함께 축소됩니다.
- **자습·노트:** 설명 패널은 본문 다음에 놓이며 노트는 별도 창으로 열립니다. 화면 회전은 현재 장·단계·퀴즈 결과를 초기화하지 않습니다.
- **모션:** 단계 시그니처는 유지합니다. 긴 읽기 페이지에서는 전체 장면 스냅샷 전환을 생략하고 내용의 등장 효과를 사용합니다. 자습·움직임 줄이기·인쇄에서는 기존 정적 정책을 따릅니다.
- **인쇄:** 좁은 화면용 CSS를 적용하지 않습니다. 기존 1920×1080 슬라이드 인쇄와 A4 요약·대본을 유지하며 이동 버튼·줌 뷰어·안내줄은 인쇄하지 않습니다.

## 저작과 검사

배치는 항상 1920×1080 좌표로 작성합니다 — 좁은 화면은 그대로 축소되므로 모바일용 재배치를 따로 설계하지 않습니다. 읽기 보조(스크롤 단계 공개·줌 뷰어)가 작은 화면의 가독성을 담당합니다.

최종 HTML을 320·390·768·1024·1920px와 휴대전화 가로 화면(844×390)에서 확인합니다. 장·모든 단계, 스크롤 단계 공개와 되돌림 유지, 다음/이전 장 이동, 장 폭의 뷰포트 맞춤과 가로 스크롤 없음, 줌 뷰어(본문 탭·두 번 탭·이전/다음·닫기), 퀴즈 탭 시 줌 미열림, 세로 안내 한 번 표시, 44px 버튼, 노트·확인 문제·자습·용어집·인쇄, 회전 후 상태를 검사합니다. 자동 데스크톱 검사만으로 모바일 통과를 선언하지 않습니다. 실제 기기·Safari 등 다른 브라우저에서 확인하지 않았다면 미검증으로 보고합니다. 시리즈는 기존과 같이 native `@scope`를 지원하는 브라우저가 필요합니다.

공통 구현은 `assets/css/responsive.css`와 `assets/js/responsive.js`입니다. `scripts/visual_assets.py`가 solo·pack·series에 넣습니다. 셸 변경 후에는 `python3 shared/dev/port.py`로 두 셸을 재생성하고 각 결과물을 다시 조립합니다. 개발 회귀 명령은 [dev/README.md](../dev/README.md)에 있습니다.

## 확인한 결함과 남은 한계

좁은 화면이 장을 세로로 재배치할 때 도식만 원본 의미를 지키고 나머지 요소의 시선 흐름·도식 연결이 어긋난다는 문제가 확인되어(phase 3), 세로 읽기를 "재배치"에서 "원본 배치 축소"로 바꿨습니다:

- 카드·행을 세로로 쌓고 SVG 라벨을 별도 목록으로 읽던 것 → 장 전체를 `transform: scale(폭/1920)`로만 축소해 도식과 지시 관계를 원본 그대로 유지합니다.
- 단계마다 탭이 필요하고 축소 글자가 읽기 어렵던 것 → 스크롤 자동 단계 공개는 유지하고, 읽기는 장 탭으로 여는 줌 뷰어(핀치·두 번 탭·이웃 장 이동)가 담당합니다.
- 글꼴 16px 바닥·행→열 재배치·도식 읽기창 규칙은 모두 제거했습니다 — 장 안 레이아웃을 건드리는 규칙이 없어야 배치가 보존됩니다.
- 퀴즈 선택지 탭이 줌 뷰어를 열면 안 되는 것 → 탭 대상이 버튼·`.chk`·탭·코드·핀 등 조작 요소면 열지 않습니다.
- 폰 가로(844×390)에서 탐색줄이 여러 줄로 부풀던 것 → 높이 ≤500px 에서는 한 줄 가로 스크롤로 유지합니다.

남은 한계: 검증은 Chromium 기준입니다. 실제 기기·Safari 등 다른 브라우저는 미확인(NOT_RUN)이므로 결과 보고에 함께 적습니다. 줌 뷰어의 장은 읽기 전용 복제본입니다(퀴즈·탭 조작은 원본에서). `?view=slide`를 작은 세로 폭에서 쓰면 화면이 좁아도 한 장 보기를 강제합니다(명시적 지정 우선).
