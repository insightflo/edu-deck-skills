> **로드 시점**: 제작 6단계(검사) — 자동 검사(check_deck 등)를 전부 통과한 뒤. 자동 검사 통과는 디자인 승인이 아니다.

# 공통 디자인 크리틱 (design-critique)

## 0. 원칙 — 이 문서는 절차 계약이지 취향 기준이 아니다

- **평가 대상은 목적·메시지 전달 부적합뿐이다.** 구현 방식·미적 선택(색 계열, 카드냐 헤어라인이냐, 장식의 유무)은 저작 에이전트의 자율이며 크리틱이 강제하지 않는다.
- 취향을 절차로 강제 금지: "더 세련되게" 같은 비언어 피드백, 근거 없는 통일·화려함 요구는 크리틱 항목이 아니다.
- 지적은 **어떤 장·어느 요소가·왜 전달을 해치는지·어떻게 바꾸는지** 네 단위로 언어화한다.
- 저작 에이전트는 자기 결과물을 스스로 평가해 통과라고 쓰지 않는다 — 크리틱은 **별도의 시각 판단 에이전트** 또는 사용자가 한다(§5).
- 정적 코드 읽기만으로 크리틱했다고 보고하지 않는다 — 실제 캡처를 본다(§3).

## 1. 절차 6단계 (전 스킬 공통)

1. **방향 설정** — 청중·목적·밀도(발표용/자습용)를 먼저 정하고, 그 위에 구도·타이포·차트 표현·리듬의 방향을 한 줄로 선언한다(예: "임원 발표용·저밀도·헤어라인 직각 구조·차트마다 시사점 1개"). 이후 판단은 이 방향에 비춰 한다.
2. **핵심 장표 조기 검토** — 표지 + 대표 1~2장을 실제 렌더링해 방향이 맞는지 확인한 뒤 전체 제작에 들어간다. 부적합하면 방향을 조정하고 다시 — 완성 후에 뒤집지 않는다.
3. **전체 제작·캡처** — 완성 후 전 장을 1920×1080 최종 상태로 캡처한다(§4 도구). 필요시 반응형·모션 중간 상태를 추가한다.
4. **독립 크리틱** — 저작 에이전트가 아닌 시각 판단 에이전트(§5)가 캡처를 보고 §2의 9항목으로 진단한다. 축소본으로 전체 리듬을 먼저 보고 대표 장을 심층 본다.
5. **수정·재검토** — 등급(§3)에 따라 Blocker는 필수 수정, Major는 개선하거나 수용 사유를 기록, Minor는 선택. 수정한 장은 재렌더링해 전후 비교 캡처를 남기고 같은 관점으로 재평가받는다.
6. **보고** — 기술 검사(자동) 결과와 디자인 검사(크리틱) 결과를 **구분해** 보고한다. 자동 검사 통과를 디자인 품질의 증거로 쓰지 않는다.

## 2. 9항목 질문표

| # | 항목 | 질문 |
|---|---|---|
| 1 | 위계·첫인상 | 3초 안에 이 장의 핵심 메시지가 눈에 들어오는가 |
| 2 | 레이아웃 다양성 | 모든 장이 비슷한 카드·박스·그리드를 반복하지 않는가 |
| 3 | 여백·공간 활용 | 여백이 의도적인가, 화면을 채우지 못한 빈 공간인가 |
| 4 | 타이포그래피 | 제목·숫자·본문·주석의 대비와 리듬이 역할 차이를 보여주는가 |
| 5 | 색·대비·정체성 | 색이 의미를 옮기는가, 이 덱만의 시각 성격이 있는가 |
| 6 | 차트·도식 전달력 | 범용 차트가 아니라 이 덱의 결론·시사점이 보이는가 |
| 7 | 모션 기여도 | 등장·강조가 이해(원인·변화·과정·비교)에 기여하는가, 장식인가 |
| 8 | 전체 리듬·일관성 | 장의 흐름(밀고 빼기)이 살고 골격·용어는 일관된채 유지되는가 |
| 9 | AI 상투 패턴 | 어느 AI가 만들어도 나올 법한 모양(균등 카드 그리드·무지성 그라데이션·장식 아이콘)은 아닌가 |

영역별 보조 질문 — 같은 절차 위에서 덧붙인다:
- **교육 덱**: 학습 목표와 이 장의 활동이 연결되는가. 학습자가 다음 단계로 넘어갈 준비가 됐는지 확인 가능한가.
- **아키텍처 장**: 구성 요소의 구조·관계·동작 순서가 도식에서 읽히는가(레인·레이어·화살표 방향의 일관성).
- **컨설팅 덱**: 차트가 결정·시사점으로 연결되는가. 펌 대비 관점은 `consulting-deck/references/design-review.md`.

## 3. 등급 — 기술 결함과 심미 문제를 분리해 표기한다

| 등급 | 정의 | 처리 |
|---|---|---|
| **Blocker** | 잘림·겹침·불가독(대비 실패)·**잘못된 시각 의미**( 데이터와 그래픽이 다르게 읽힘, 핵심 메시지 불가시) | 필수 수정. 남기면 납품 중단 |
| **Major** | 위계 실패·배치 반복·메시지에 부적합한 표현 | 개선하거나 수용 사유를 기록 |
| **Minor** | 미세한 어긋남·리듬 손상 | 선택 |

- 기술 결함(겹침·잘림·렌더 오류)은 자동 검사(check_deck) 소관이지만 크리틱에서 발견되면 기술 결함으로 표시해 코드 수정한다 — 심미 등급에 섞지 않는다.
- 정렬·간격 손보기로 끝내는 polish를 "크리틱 반영"이라 주장하지 않는다 — 필요하면 조형 구조·배치 자체를 다시 설계한다.

## 4. 캡처 도구

```bash
python3 <base>/scripts/capture_deck.py <덱.html> <출력폴더>    # 전 장 1920×1080 + revisit, --narrow 로 1280×720 추가
```
- 최종 상태 기준: 도구가 `deckGo(i, 99)`(모션 완결)로 이동해 찍는다. 모션 중간 프레임은 결함으로 오탐된다.
- 축소본(썸네일 그리드)은 전체 리듬·실루엣 반복 점검용 — 개별 장 판단은 원본 캡처로.

## 5. 독립 크리틱 에이전트 (환경 계약)

- 크리틱은 **저작 에이전트와 다른** 시각 판단 에이전트가 한다. 이 환경에서는 agy(gemini-4-argon) — 호출:
```
hc run --name <이름> --bg agy --dangerously-skip-permissions    # 플래그 필수 — 없으면 권한 프롬프트로 멈춘다
hc send <주소> '<브리프>'
```
- 브리프에 포함할 것: 캡처 폴더(저장소 안 gitignore 폴더 — 예: workspace/, 검사 뒤 삭제), 9항목 질문표, 등급 정의, 보고 파일 경로, **구현·수정 금지, git 금지**(검사 에이전트는 진단만).
- 보고 형식: 판정(대상별 PASS/FAIL)·Blocker/Major/Minor(장 번호+요소+현상+제안)·결론.
- 시각 판단 에이전트를 쓸 수 없는 환경이면: 사용자에게 크리틱을 요청하거나, 캡처와 자기 점검 결과를 "독립 크리틱 없음"으로 명시해 보고한다 — 독립 크리틱을 한 것처럼 쓰지 않는다.

## 6. 각 스킬에서의 자리

- **edu-deck-solo** 6단계 — 자동 검사 통과 뒤 이 문서 절차 실행(1~2단계 방향·조기 검토는 1·3.5·4단계와 겹치면 그 기록을 재사용).
- **edu-deck-series** 4단계 — 편마다 solo 기준 크리틱 + 시리즈 전체(포털·목록·편 간 리듬) 크리틱 1회.
- **consulting-deck** 6단계 — 이 문서 + `references/design-review.md`(펌 대비·방향 시안 절차).
- **Architecture Kit** — 아키텍처 장이 주인공인 덱은 보조 질문(구조·동작)으로 심층.
- **팩/legacy 교육 덱** — 선택 계약(주흐름 일관)과 학습 성과 증거 관점을 포함.
