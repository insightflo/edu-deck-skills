> **로드 시점**: 슬라이드에 개념 SVG 도식(개념도·흐름도·관계도·장면)을 넣을 때. 기본(legacy) 경로와 팩 경로 모두에서 같은 문법을 쓴다.

# 개념 SVG 도식: 장의 주인공을 그림으로

내용 장의 본문은 개념을 그린 인라인 SVG가 주인공이다. 개념·구조·관계·흐름을 그림으로 보여 주고 글은 짧은 라벨로 붙인다. 카드 3~4개 가로줄 같은 텍스트 상자 나열로 도식을 대신하지 않는다(퀴즈·체크리스트·참고 자료 장은 각 조각의 형식을 따른다). 도식은 정적 최종 화면만 만들고, 단계 등장은 `data-step`에 맡기며 움직임은 공통 엔진이 재생한다.

## 1. 설계 규칙

- **장마다 도식의 자리를 먼저 정한다.** 어떤 도식이 어디에 들어가는지를 저작 전에 정한 뒤 조각을 만든다. 마지막에는 전 장 축소판(contact sheet — 빌드 결과물 `덱.html?sheet` 로 연다. `?sheet=2`~`6` 으로 단 수를 바꾼다. 전 장이 전개된 완성 모습에 번호표가 붙는다)을 직접 보고 빈 곳·쏠림·반복을 판단한다. 검사기 통과는 디자인 승인이 아니다.
- **아래까지 균형 있게 채운다.** 제목 아래부터 화면 아래쪽(1920×1080에서 약 y 950px)까지 도식이 차지한다. 하단 절반이 비지 않게 하되 빽빽하지도 않게 한다.
- **단계로 쌓는다.** `<g data-step="N">`으로 그림이 쌓이게 한다(장당 2~5단계, 최대 7). 마지막 단계에서 완성 그림이 보이고, 정리 문장(callout)을 두면 마지막 단계에 둔다.
- **없는 관계를 그리지 않는다.** 도식이 자료에 없는 관계(순서·인과·수치·비율)를 만들어 내지 않는다. 화살표·위치·크기·개수는 조사된 내용의 관계만 담는다.
- **한 그림에는 답할 질문을 하나만 둔다.** "이 그림을 보고 뭘 알아야 하나"를 먼저 정하고 그 질문에 맞는 문법을 고른다(연결·순서·과정·상태·포함·비교 — `composition.md` 5절의 내용→아키타입 표). 질문 여러 개를 한 그림에 욱여넣지 않는다 — 뷰를 나누거나 단계로 겹쳐 보인다.
- **같은 둥근 상자 + 화살표의 기계적 반복을 피한다.** 서비스·사람·자료·경계·변환이 전부 같은 모양·같은 무게일 필요는 없다 — 종류가 다르면 도형 어휘(`k-blue` 원, `k-paper` 카드, `k-frame` 점선 틀)와 크기를 다르게 한다.
- **위계는 색보다 먼저 위치·묶음·포함·크기·여백으로 세운다.** 색은 마지막 수단이다.
- **라벨은 기본 화면에서 읽힌다.** 중요 글자를 회전시키지 않고, 붐비는 선 위에 올리지 않는다.
- **연결선은 노드·라벨을 피해 길을 잡는다.** 방향은 화살촉으로 분명히 하고, 뜻이 다른 선은 선 클래스를 다르게 한다(`k-ln-o`/`k-ln-b`/`k-ln-n`/`k-ln-g`).
- **틀(`k-frame`)은 소유·책임·신뢰 경계를 말할 때만 쓴다.** 장식용 점선 테두리가 아니다.
- **팬·줌은 쓰지 않는다.** 고정 무대(1920×1080)에 도식이 안 들어가면 장을 나누거나 그림이 답할 질문을 줄인다 — 덱은 지도 앱이 아니다.
- **화면에는 청중이 쓰는 개념을 그린다.** 파일명·클래스명 같은 구현 이름은 코드 구조가 그림의 질문일 때만 넣는다.
- **가상·개념 표기.** 가상 예시는 "가상 예시", 모양이 수치처럼 보이는 그림(빙산·사분면·개념 곡선)에는 "개념도 · 측정값 아님"을 표기한다. HTML에서는 `<p class="k-note">가상 예시</p>`·`<p class="k-note">개념도 · 측정값 아님</p>`를 쓰거나(점선 테두리로 사실 칩 `.fact`와 구분), SVG 안 라벨로 표기한다.
- **사실과 연결한다.** 도식 안의 숫자·날짜·조항도 `.fact[data-src]` 칩 계약의 대상이다. 칩 밖 수치 검사는 SVG 글자까지 훑으므로, 도식에 쓴 수치는 같은 장 칩 글자에 그대로 있어야 한다.

## 2. SVG 문법

- `<svg class="dg" viewBox="0 0 1664 H" role="img" aria-label="한 문장 설명">`: 전폭 기준 1664px(1:1 좌표계). `.dg`는 셸이 너비 100%·글꼴 상속을 준다. 좁은 svg는 style width를 viewBox 폭과 같게 둔다 — 자동 축소로 글자 실제 크기가 작아지는 것을 막기 위해서다(18px 미만 ERROR, 20 미만 WARN).
- **SVG 글자는 항상 클래스로 쓴다**(고정 px·색을 직접 적지 않는다): 셸 `t-h`(38 굵게)·`t-l`(26 굵게)·`t-s`(26 보조, `.o` 주황·`.b` 파랑)·`t-q`(24 굵게, 종이 테두리)·`t-badge`(26 종이색) + 공통 `k-t-hero`(48 굵게)·`k-t-tag`(22 굵게 회색)·`k-t-w`(흰 글자)·`k-t-o`(주황 글자)·`k-t-b`(파랑 글자).
- 개념 원은 r≈96~118 + `<use href="#i-…" style="color:var(--deck-blue)">`, 이름 `t-l`/`t-h` + 설명 `t-s` 두 줄(원 아래). 번호 원은 r20 `fill var(--deck-blue)` + `t-badge`.
- 흐름선은 `class="dash-flow k-ln-o" marker-end="url(#ah-o)"`처럼 `dash-flow`에 덱 선 클래스·화살촉을 단다. `dash-flow`는 공통 엔진이 필요한 순간에만 선/입자를 재생하는 표식이므로 지우지 않는다.
- 색은 셸 토큰(`var(--accent)`·`var(--blue)`·`var(--ink)` 등)과 덱이 정의한 `var(--deck-*)`만 쓰고 고정 hex를 적지 않는다. `--deck-*` 변수는 도형 채움·선·장 배경 전용이며 글자 색으로 쓰지 않는다(작은 글자 대비 검사가 깨진다).

### 공통 어휘 (셸에 이미 들어 있음)

아래 도형·글자 클래스는 공통 `assets/css/visual-motion.css`(색은 tokens.css 토큰), 화살촉·`i-robot`은 공통 `assets/icons/extra.svg`에 들어 있어 기본 경로·팩 경로 덱 모두 따로 정의하지 않고 바로 쓴다(목록: `classes.md`·`icons.md`). 덱 고유 색이 필요하면 `src/deck.css`에서 같은 클래스를 덮어쓰고, 같은 id의 덱 `src/icons.svg` 기호는 공용 기호를 덮어쓴다. 참고 덱: `im-human/outputs/edu-deck-solo/20261103-agent-communication/`.

- 도형 클래스: `k-frame`(점선 크림 틀)·`k-blue`(파랑 개념 원/면)·`k-orange`(주황 면)·`k-paper`(종이 카드)·`k-gray`(회색 면)·`k-solid-o`/`k-solid-b`/`k-solid-n`(꽉 찬 주황/파랑/남색)·`k-ln-o`/`k-ln-b`(굵기5 선)·`k-ln-n`(굵기4 먹선)·`k-ln-g`(회색 점선).
- 화살촉 marker: `ah-o` 주황 · `ah-b` 파랑 · `ah-n` 먹색. 셸 기본 `ah`/`ahb`/`ahg`/`ahk`(`icons.md`)와 색이 다르므로 선 클래스(`k-ln-o`/`k-ln-b`/`k-ln-n`) 색과 맞는 화살촉을 쓴다.
- 보조 아이콘: `i-robot`(에이전트처럼 일을 맡는 프로그램을 사람 아이콘과 구분해 그릴 때). 나머지 아이콘은 공통 `icons.md`의 `i-*` 목록에서 고른다.

## 3. 함정 (셸 CSS·조각과의 충돌)

- 셸 CSS `.slide svg rect[rx]{rx:var(--r2)}`가 rx 속성 있는 rect의 모서리를 16px로 강제한다. 다른 반경이 필요하면 `style="rx:Npx"`로 지정한다.
- `.tile rect`는 종이색 채움·accent-light 선으로 강제된다. 색 있는 타일이 필요하면 `.tile` 조각 클래스 대신 일반 `g`로 그린다.
- 어두운 장(`.dark`·`.cx`)의 SVG 글자는 기본 잉크색이 배경에 묻힌다. `style="fill:var(--paper)"`·`var(--light)`처럼 면에 맞게 밝힌다. 주황 면 장(예: `.slide.orange`)은 먹색 글자만 쓴다. SVG 글자는 대비 자동 측정 대상이 아니므로 눈으로 확인한다.
- svg 안에 `<script>`·SMIL(`animate*`)·CSS 애니메이션을 넣지 않는다. 조각은 정적 최종 화면만 만들고 단계 재생은 공통 엔진이 맡는다.
- 외부 이미지·웹 캡처를 쓰지 않는다. 라스터가 꼭 필요하면 덱당(시리즈는 편당) 합계 1.5MB 이내 base64만 넣는다.

## 4. 공용 그림 자리 (fig-slot)

장 배치 조각이 텍스트 자리(`«제목»`·`«설명»`)를 미리 깔아 두듯, 일반 배치 계열도 **SVG 그림 자리를 미리 마련**할 수 있다 — `<figure class="fig-slot">`. 자리·비율·정렬은 배치(계열 변형)가 지정하고, 내용은 저작 에이전트가 이 문서의 문법으로 그린다. 예전 슬라이드가 "사진·이미지를 붙여 넣고 설명"하던 자리를, 에이전트가 그린 시각 체험(도식·모형)으로 바꾸는 공용 계약이다 — 도식 16계열 전용이 아니다.

- **형태**: `<figure class="fig-slot" data-step="N"><svg class="dg" viewBox="…" role="img" aria-label="한 문장 설명">…</svg><figcaption>선택</figcaption></figure>`. 슬롯은 섹션에 하나다 — 텍스트 자리 규약(`«…»`)과 병행 가능.
- **내용**: §2의 `svg.dg` 문법 그대로 — `k-*` 도형·`t-*` 글자·화살촉(`ah-*`), 색은 슬라이드 토큰만. viewBox 폭은 슬롯 폭에 맞게 고른다(전폭 1664 기준을 그대로 쓰면 자동 축소로 글자가 작아진다 — 슬롯이 장의 절반이면 720~860 정도).
- **단계**: 슬롯 자체의 `data-step`과 내부 `g[data-step]` 모두 도식 계열과 같은 계약으로 쌓인다. 슬롯의 등장은 계열 시그니처를 따른다(신규 시그니처를 만들지 않는다).
- **인쇄·자습·reduced-motion**에서는 마지막 단계의 완성 모습이 그대로 보인다 — 정적 최종 화면을 그리는 원칙은 도식과 같다.
- **검사**: 빈 슬롯·`«…»` 자리표시 잔류·`role="img"`+`aria-label` 누락은 `check_deck.py` ERROR(텍스트 자리와 같은 취급). 변형 스니펫은 견본 svg를 얹어 배포하므로, 저작할 때는 견본을 지우고 주제에 맞게 다시 그린다.
- **현재 슬롯을 싣는 변형**: agenda·traits-grid·levels·statement·rules-dark 의 `data-variant="fig"` (layouts.md '그림 자리와 텍스트 나열' 절).
