> **가이드 문서**: 자유 모드에서는 참고 예시이고, 막혔을 때·가이드 모드일 때 따른다.
> **로드 시점**: 4단계 슬라이드 조각을 쓸 때(글 쓰는 법, 색 의미, 단계 등장). 검사에서 글자 크기·대비 경고가 나오면 다시 본다.

# 표현 형식: 글 · 색 · 글자 · 움직임

## 1. 문장

- 존댓말(-ㅂ니다 / -세요). 한 문장에 한 내용. 짧고 쉬운 말.
- 숫자는 아라비아 숫자 + 단위(2시간, 20분, 33℃, 3가지). 날짜는 `2026. 10. 30` 또는 `2026-10-30` 중 한 가지로 통일.
- 말로 하는 예는 겹따옴표 “…”. 묶음은 가운뎃점(물·그늘·휴식). 흐름은 →. 구조도 번호는 ①②③④.
- 이모지, 느낌표 연발, "~하는 것이 중요합니다" 같은 빈 문장, 영어 남발을 쓰지 않는다. 영어 용어는 처음 한 번 `.en` 으로 작게 붙인다.
- 외국어 문장(영어 원문·제목·인용·질문·설명)은 자연스러운 한국어로 옮겨 적어 화면에 보인다. 원문을 작게 곁들이지 않는다. 사람·기관·제품·모델·데이터셋 이름, 지표·약어, 코드·명령·파일 경로·URL, 화면에 실제로 영어로 나오는 메뉴 이름은 원문 그대로 둔다. 원제 비교가 필요하면 번역 뒤 괄호로 붙인다. 번역은 숫자·이름·단위를 바꾸지 않는다. 화면 글에 라틴 문자 단어가 6개 이상 연속되면 검사가 `외국어 문장` 취향 항목을 낸다(기본 INFO, `--style` 에서 WARN. 코드·키 캡·사실 칩·출처 캡션·URL·SVG 글자·노트는 제외).
- 화면 글은 발표자가 말할 내용을 다 담지 않는다. 말할 것은 노트로 보낸다.

### 제목 유형 (참고 덱 42개 제목의 분포: 주장형·조언형 14, 정의형 9, 질문형 3, 이름표형 16)

| 유형 | 모양 | 예 (다른 주제) |
|---|---|---|
| 주장형 | …합니다 / …입니다 | 폭염 피해는 오후 2~5시에 몰립니다 |
| 조언형 | …하세요 | 보고서는 결론부터 쓰세요 |
| 질문형 | …일까요? / …할까요? | 이 메일, 그대로 보내도 될까요? |
| 비교형 | A와 B는 무엇이 다를까요? | 손익계산서와 현금흐름표는 무엇이 다를까요? |
| 정의형 | 용어: 일상 비유 | 현금흐름표: 회사의 통장 입출금 내역 |
| 예시형 | (동사)하기 | 작업 전 점검표 채우기 |

"개요", "현황", "주요 내용" 같은 이름표 제목은 쓰지 않는다. 예시 장은 예시형으로 짧게 쓴다.

- 제목이 지정 줄 수를 넘으면 `.title` 에 `data-fit` 을 붙여 최대 20%까지 줄인다(기본 1줄, `data-fit="2"` 로 2줄 허용). 그래도 넘치면 검사가 `제목 줄 수` 취향 항목을 낸다(기본 INFO, `--style` 에서 WARN. 속성·뷰어 키는 [classes.md](classes.md) "뷰어 도구" 절).
- 발표 덱(talk)은 제목을 결론 한 문장으로 한 줄에 쓰고, 말할 내용은 노트(대본)로 보낸다 — [발표 덱(talk 모드)](talk.md).

### 2톤 헤드라인(em.t2)

- 근거: momentic.ai 헤드라인 분석 — "Catch bugs before they ship."처럼 모든 큰 헤드라인에서 마지막 단어만 색을 바꾸면 사이트 전체에 일관된 리듬이 생겨 템플릿이 아니라 문서 같은 인상을 만든다.
- 큰 제목(`.pack-prompt`, `.big`)에서 핵심 어절을 `<em class="t2">`로 감싸면 강조색(--accent-text)이 붙는다. 문장당 1회, 어절 1~2개 이하, 주로 문장을 닫는 마지막 어절에 쓴다.
- 색만 바뀐다. 기울임은 없다(Pretendard에 이탤릭 자형이 없다). 어두운 면(legacy `.dark`, field의 sign면)에서는 accent-text 대신 accent-light이 적용된다.
- `.title` 표지 제목, 눈썹, 본문, 카드 제목에는 쓰지 않는다. 문장마다 마킹을 반복하지 않는다 — 리듬은 절제에서 나온다(마킹 과다는 체커가 아니라 이 규칙으로 제어한다).

### 확인 문제(.chk) 문장

- 질문은 헷갈리기 쉬운 것 하나만 겨낸다: "~은/는 ~인가요?" 형태. 정답이 한눈에 보이는 질문은 피한다.
- 보기는 서로 확실히 다른 문장(기본 2개) 또는 짧은 명사구(확장 4개). "~아니다" 같은 부정형 남발은 쓰지 않는다.
- 해설(.chk-why)은 왜 정답인지 한두 문장. 문제를 다시 가르치지 않고, 틀린 사람이 다시 보게 될 장의 핵심만 짚는다.
- 눈썹은 `확인 문제 N / M` (진행 상황이 보이게). 퀴즈와 달리 발표 중 청중에게 직접 누르게 할 수 있다.

### 숫자 증거 스트립(.stat-strip)

- 근거: momentic.ai 분석 — 히어로 바로 아래 확인된 지표를 나열하는 것이 「마케팅 문구만으로 신뢰를 만들지 않는다」는 원칙의 핵심 장치다. 교육 덱에서는 조사로 모은 정량 근거가 표지와 목차에서 가장 약하게 표현된다.
- 지표 3~6개 = 큰 숫자(아라비아 숫자·쉼표·% 만, 단위는 라벨에) + 한 줄 라벨. 지표마다 `data-src="Fxx"` 사실 id 를 단다(누락·없는 id 는 검사 ERROR). 확인 단계가 원문대조·두출처일치인 사실만 쓴다.
- **배치 규칙: 표지 하단 / 목차 상단 / 마무리 상단 중 한 곳에만 1회.** 본문 중간에 반복해 넣지 않는다 — 증거가 흩어지면 신뢰가 약해진다(이 규칙은 문서 규칙으로만 통제한다).
- 등장 시 metric-rally 시그니처가 숫자를 카운트업한다(셸 소유). reduced-motion·인쇄·자습에서는 항상 최종 값이 그대로 보인다. 조각: `assets/snippets/31-stat-strip.html`
- **길이=값 원칙(정직한 수치).** 숫자 아래 장식 막대·게이지는 그 길이가 실제 값에 비례할 때만 쓴다 — 막대는 데이터 인코딩이다. 비율을 못 지키면(단위가 섞임·분모 불일치·근거 없는 임의 %) 막대를 금지하고 숫자+단위만 보인다. 0은 0길이, N/A는 임의 길이 금지(glm-vs-ours §4-7, Blocker 급 시각 의미 결함 예시: KLIC O12).

### 실물 화면 인용(.screen-cite)

- 근거: momentic.ai 분석 — 제품 UI 를 브라우저 프레임째 「있는 그대로」 배치하는 것이 가장 강한 신뢰 장치다. 모형 창이 "이렇게 생겼다"를 흉내 낸다면 실물 화면 인용은 "실제로 있다"를 보여 준다.
- **이미지는 사용자가 제공한 것만 허용한다.** 에이전트가 웹을 돌아다니며 임의로 캡처해 넣는 행위는 금지한다(출처 불명·저작권). 제공 이미지가 없으면 이 조각을 선택하지 않는다 — 프레임만 있는 빈 조각은 검사 ERROR다.
- 구조: 브라우저 창 프레임(주소창·탭은 순수 CSS 모형) + base64 이미지 + 캡션 3요소 — 출처(도메인·문서명, `data-src="Fxx"` 사실 id) · 조회일 · 「이 화면이 증명하는 것」 한 줄 요지. alt 는 화면의 요지를 말해야 한다(빈 alt·장식 문구 검사 ERROR).
- 예산: 이미지 1장 ≤700KB 권장(초과는 취향 항목, 기본 INFO), 덱 라스터 합계 1.5MB 이내(초과 ERROR — 기존 규칙을 체커가 검사한다).
- 배치: 기본은 mapping 호스트(좌 실물 화면 + 우 번호 카드), 비교 변형은 compare-2(screens — 좌우 실물 화면 비교). 모션은 호스트의 기존 시그니처(paired-connection·opposed-faces)가 발화한다 — 이 그림 자체는 새 시그니처를 갖지 않는다. 조각: `assets/snippets/32-screen-cite.html`

## 3. 색의 의미

15개 의미 역할과 팩별 값은 [DESIGN_TOKENS.md](DESIGN_TOKENS.md)와 `assets/css/tokens.css`가 기준입니다. 이 문서에 색 값을 복제하지 않습니다. 색·반경·선·그림자·간격·시간은 공통 토큰을 사용합니다.

- **주황** = 해야 할 것, 새로 바뀐 것, 오늘의 핵심, 비교의 오른쪽(새 방식).
- **파랑** = 묻는 것, 정답, 근거 있는 사실(칩), 비교의 왼쪽(기존 방식).
- **어두운 슬라이드** = 꼭 지킬 규칙(rules-dark), 위험 파트를 여는 문장(statement dark), 마무리.
- **주황 전면** = 파트를 여는 핵심 문장(statement orange). 덱에 1~2장.
- 색만으로 뜻을 전하지 않는다. 정답은 색 + 글자(O/X, "정답") + 위치로 함께 보인다.
- 회사 색으로 바꿀 때는 덱 `src/brand.css` 에서 `:root` 토큰만 덮어쓴다. 의미(주황=행동, 파랑=근거)는 유지한다.

## 4. 글자 크기 (1920×1080 기준 px)

| 클래스 | 크기·굵기 |
|---|---|
| `.big` | 96 / 800 |
| `.title` | 72 / 800 |
| 표지 제목 | 160 (한 줄에 안 들어가면 128 → 104 자동, 그래도 길면 104 두 줄) |
| `.card h3` | 44 / 700 |
| 증거 숫자 `.stat-num` | 56 / 800 |
| `.body`, `ul.list` | 32 |
| `.small`, `.label`, 눈썹 | 28 |
| 모형 창 안 글 | 20~26 |
| **최소** | **20** (18 미만은 검사 ERROR, 20 미만은 취향 항목) |

- 참고 덱보다 바꾼 점: 18px 꼬리표·16px 아바타 글자를 20px로, 회색 번호와 주황 원 바탕을 조금 진하게 했다(대비 3.0 이상). 모양과 배치는 같다.
- 대비 기준(검사기): 24px 이상 또는 굵은 19px 이상은 3.0, 그보다 작으면 4.5. 모형 창 안은 3.0. 모든 단계에서 재며 위반은 ERROR 로 보고한다. 8팩 토큰 대비 매트릭스는 `check_deck.py --contrast-matrix` 로 전수 채점한다. 배경 판정은 글자에 가장 가까운 불투명 배경색을 쓰고, 카드·판 위 글자도 같은 기준이다. 그라데이션·배경 이미지 위 글자는 면제가 아니라 렌더 픽셀을 샘플링해 최악 대비로 잰다 — 카드·판 위에도 어두운 토큰(`--ink`·`--soft`·`--accent-text`)을 써야 한다.
- 본문 글자는 24px 이상으로 쓴다(모형 창 안 20~26px 같은 본문이 아닌 자리는 제외). 내용이 넘치면 글자를 줄이지 않는다 — 장을 나누거나 자세한 내용은 노트로 옮긴다. 검사기 하한(18 미만 ERROR·20 미만은 취향 항목)은 절대 하한이고 24px는 저작 규칙이다.

## 5. 단계 등장

| 속성 | 뜻 | 쓰는 곳 |
|---|---|---|
| `data-step="k"` | k단계부터 보임(튀어나오기, AI 말풍선 `.a` 는 생각 중 점 뒤 등장) | 읽는 순서대로 하나씩 |
| `data-add="k"` | k단계부터 보이고 그 단계에서 주황 형광 | 문장에 덧붙인 부분(build-up, 고친 줄) |
| `data-only="k"` | k단계에만 보임 | 상태 바꾸기: 전→후, 질문→답, 막대 값 |
| `data-lit="k"` | k단계부터 `.lit` 강조 | 정답 카드, 1등 막대, 고리 조각, 강조 칸 |
| `data-until="k"` | k단계까지만 보임 | 사라지는 안내·빈칸 |

- 정리 문장(callout)은 마지막 단계. 퀴즈 정답은 별도 단계(먼저 청중에게 묻는다).
- 보통 2~5단계, 7단계 이하. cover·statement·sources·closing 은 0단계.
- 단계 번호는 1부터 빈틈없이. 같은 번호에 여러 요소를 묶어도 된다.

단계 등장 3원칙 (한 덱 전체에서 지킨다):
1. **속도의 통일** — 단계는 누를 때마다 같은 리듬으로 반응한다. 장마다 등장 속도·묶음 크기를 다르게 하지 않는다.
2. **의미 있는 단계** — 단계는 읽는 순서·정보 덩어리 단위로만 나눈다. 장식용·시간 끌기용 단계는 만들지 않는다.
3. **시각적 안정성** — 어느 단계에서 멈춰도 넘침·잘림·겹침이 없어야 한다(검사가 모든 단계에서 잰다). 등장 전 상태와 마지막 상태 둘 다 완성된 화면이어야 한다.

**모션은 셸 한 곳에서 소유합니다.** `data-archetype`에 따라 42개 실행 시그니처를 선택하며 52 조각 계열·253 변형을 지원하고, `data-fx`로 부르는 공통 기법 9종(scatter-gather·slice-reveal·row-mask-rise·weight-wave·rack-focus·bar-grow·card-deal·blinds·draft)이 덧붙습니다. 장 전환·공유 제목·단계 재생·정적 대체는 [MOTION_LIBRARY.md](MOTION_LIBRARY.md)를 따릅니다. 조각에는 CSS 애니메이션·SMIL·스크립트를 넣지 않습니다. 기본은 transform/opacity, 승인된 예외는 제목 blur·SVG 선 드로잉에 더해 slice-reveal·blinds의 clip-path·rack-focus의 filter blur·weight-wave의 가변 wght, 그리고 draft의 캔버스 드로잉(aria-hidden 오버레이, 유한 2400ms, 종료·취소 시 제거 — 최종 모습은 저작 이미지 그대로)입니다. reduced-motion·인쇄·자습에서는 현재 의미 단계의 정적 완성 화면을 보입니다. 속도·대비·넘침은 실제 검사로 확인하며 GPU 속성만으로 성능을 보장하지 않습니다.

강조 효과 `data-fx` 도 같은 엔진의 저작 속성입니다([MOTION_LIBRARY.md](MOTION_LIBRARY.md) "강조 효과 data-fx" 절):

- 이야기가 있는 장면만 움직입니다 — 문제→해결, 이전→이후, 강조할 숫자 하나. 나열 장에는 붙이지 않습니다.
- 한 장에 1~2개, 눈이 갈 곳은 하나. 한 장의 효과는 3초 안에 끝냅니다(검사 "모션 길이").
- 마지막 모습만으로 뜻이 통하게 씁니다(`count` 본문은 최종값). 한 요소 한 효과 — `data-crayon` 과 같은 요소에 쓰지 않습니다.

## 6. 그림 규칙

- 기본 아이콘은 선 아이콘(`references/icons.md`)입니다. 임팩트 순간의 소량 컬러 변형은 공통 토큰만 씁니다. 이모지는 설명 도식을 대신하지 않습니다.
- 인라인 SVG 일러스트·도식은 적극 권장합니다. 라스터가 꼭 필요하면 base64로 넣고 덱당 합계 1.5MB 이내로 제한합니다. 실물 화면 인용(1절 `.screen-cite`)의 이미지는 사용자가 제공한 화면만 허용합니다 — 에이전트가 웹을 돌아다니며 임의 캡처해 넣는 행위는 금지합니다(출처 불명·저작권). 제공 이미지가 없으면 그 조각을 선택하지 않습니다(빈 프레임은 검사 ERROR). 외부 이미지·CDN·외부 글꼴 로딩은 계속 금지합니다. Pretendard 원본은 셸에 라이선스와 함께 임베드하며 이미지 예산과 별도입니다.
- 비유·예시에는 도식·일러스트·업무 장면 중 하나를 짝지어야 합니다. 문장만 있는 본문은 statement와 퀴즈 질문 정도로 제한합니다. `check_deck.py`의 ‘시각 짝’ 취향 항목은 저자가 의미를 확인해야 합니다.
- 도식은 조각 안의 인라인 SVG 를 고쳐 쓴다. 번호 원(①②…)을 붙이고 오른쪽·아래 설명과 짝을 맞춘다.
- 모형 창(`.win`)은 "실제 일에서는 이렇게 생겼다"를 보여 주는 곳이다. 대화형 도구면 채팅 모형, 아니면 문서(`.doc`)·표(`.xl`)·양식(`.fm`)·메일(`.mail`)·단체방(`.msgr`) 모형.
- 모형 안 이름·회사·숫자는 그럴듯한 가상 값. 실제 개인정보 금지.
- 장식(번짐 원, 점 연결망, 뒤에 깔린 카드)은 `aria-hidden="true"`.
- 한 장 최대: 카드 4개 한 줄, 칸 8개, 목록 5항목(6 초과 취향 항목), 단계 7.

## 7. 피할 것

- 글머리표만 가득한 장, 문단을 통째로 붙인 장, 한 장에 두 메시지
- 이름표 제목("개요"), 출처 없는 숫자, 확인 못 한 숫자를 화면에 쓰기
- 20px 미만 글자, 작은 주황 글자에 `--accent` 쓰기
- 뜻 없는 장식·아이콘, 색만으로 정답 표시
- 말투 섞기(반말, 한 장·한 목록 안에서 존댓말 문장과 명사형 끝맺음 혼용). 제목의 정의형·예시형(1절)은 괜찮다
- 참고 덱의 AI·사내 도구 문장을 옮겨 쓰기(구성·배치·표현만 따른다)
