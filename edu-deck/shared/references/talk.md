> **로드 시점**: 사람이 말하며 넘기는 발표 덱을 만들기로 했을 때(저작·검사 전). `deck.json` 에 `talk` 를 쓰면 이 문서가 적용된다.

# 발표 덱(talk 모드)

## 언제 쓰나

- 교육 덱(기본)은 듣는 사람이 혼자 넘기며 읽고 자습·퀴즈로 스스로 확인한다.
- 발표 덱(talk)은 사람이 화면 앞에서 말하며 넘긴다. 화면은 말의 뼈대일 뿐이고 설명은 발표자가 한다. 강의·브리핑·워크숍 진행용이다.
- 셸·자습·퀴즈·용어집 계약은 교육 덱과 같다. 나중에 자료로 돌려 보는 사람을 위해 남겨 둔다. 다른 것은 저작 원칙과 발표 도구뿐이다.

## 저작 원칙 (교육 덱과 다른 부분)

- **제목은 결론 한 문장, 한 줄.** 「개요」 같은 이름표 대신 그 장의 결론을 한 문장으로 쓴다. 넘치면 `data-fit` 으로 20%까지 줄이고, 그래도 넘치면 장을 나눈다.
- **화면엔 결론·숫자만.** 문단을 옮겨 적지 않는다. 한 장에 큰 그림(도식·수치·비교) 하나. 근거·사례·풀이는 말로 한다.
- **설명은 노트 = 대본.** 기존 발표자 노트(`aside.notes`)가 그대로 발표 대본이 된다. 말할 문장을 통째로 적고, 분량은 검사가 장 시간 × 읽기 속도로 본다.
- **움직임은 2~3초 안에.** 단계 등장은 말의 리듬을 방해하지 않게 짧게 끝낸다. 화면이 노는 시간을 만들지 않는다.

## 켜는 법과 데이터

`deck.json` 에 발표 계획을 쓴다:

```json
{ "talk": { "total": 1500, "rate": 300 } }
```

- `total` 은 발표 목표 시간(초), `rate` 는 분당 읽기 속도(음절 수, 기본 300)다.
- 각 슬라이드에 `data-sec="<이 장 예상 초>"` 를 붙인다.
- 대본은 기존 노트(`aside.notes`) 그대로다. 새 문법은 없다.

## 발표 도구 (talk 덱에서만 나타난다)

- `T` 타이머 시작·멈춤 · `R` 타이머 처음부터 · `V` 발표자 보기 · `N` 노트(대본) 열기.
- 상단 시계는 흐른 시간과 이 장까지의 계획 누적을 보여 주고, 계획보다 뒤처지면 붉게 변한다.
- 노트 패널 머리에 이 장 예상 초와 "~mm:ss까지" 누적이 붙는다.
- **발표자 보기**: `V` 로 새 창(`?presenter`)을 연다. 현재 장·다음 장 미리보기·대본·타이머·이전/다음 단추가 있고 본 화면과 양방향으로 동기한다. 발표 화면(빔·외부 모니터)과 발표자 보기(노트북)를 두 화면으로 나눠 쓴다. 팝업이 차단되면 안내가 뜬다 — 발표 전에 브라우저 팝업 허용을 확인한다.
- talk 덱이 아니면 위 도구·키가 전혀 나타나지 않는다(교육 덱은 그대로).

## 조립 · 연습 · 검사

- 조립은 같은 `build_deck.py` 다. 연습표는 `--notes` 로:
  ```bash
  python3 <base>/scripts/build_deck.py <작업 폴더> --notes <작업 폴더>/리허설.md
  ```
  장마다 번호·제목·예정 초·누적 시각·대본 읽기 어림 초·대본을 마크다운으로 쓴다. 리허설 때 출력해 두면 편하다.
- check_deck 이 talk 덱에만 4가지 WARN 을 낸다: ① `data-sec` 누락 ② Σ`data-sec` 가 `total` 과 ±10% 이상 어긋남 ③ 대본 분량 초과(장 시간 × rate ÷ 60 × 1.1) ④ 제목 2줄 이상(1줄 원칙). talk 경고 0이 통과다.
- **시간 배분은 목표보다 5~10% 짧게.** Σ`data-sec` 를 `total` 에 꽉 채우지 말고 질문·지연 여유를 남긴다.
- 통과 후에는 `V` 발표자 보기를 실제로 열어 두 화면 운용까지 확인한다.
