# 실행 환경별 사용 안내

`research.md` 3절의 조사 경로와 하위 스킬의 제작·검사 기준이 공통 규칙이다. 특정 제품의 이름이나 ZIP 업로드 성공만으로 실행 능력을 판단하지 않는다. 실제 사용할 환경에서 아래 능력을 확인한다.

## 공통 확인

- 파일을 풀고 읽고 쓸 수 있는가? 세 스킬을 이웃 폴더로 유지한다. 단일 루트 배포본에서는 `bundle/` 안의 세 폴더가 원본이다.
- Python 실행이 가능한가? `python3 <base>/scripts/env_check.py`로 모듈·브라우저·네트워크 상태를 확인한다. Windows 등에서는 같은 Python 인터프리터의 명령이 `python`일 수 있다. `<base>`는 현재 원본 `edu-deck/shared/`의 실제 경로다.
- 환경 확인 스크립트는 네트워크 요청을 한 번 보내며, 종료 코드가 항상 0이다. 출력 항목별 상태를 읽어야 한다. 한 사이트의 접속 실패가 모든 네트워크의 실패를 뜻하지는 않는다.
- 조립은 Python과 포함된 파일을 사용한다. 전체 검사는 BeautifulSoup4·lxml·Pillow·Playwright와 실행 가능한 Chromium/Chrome이 필요하다. 의존성이 없으면 사용자 승인 없이 설치하지 않는다.
- `check_deck.py`·`check_series.py`의 실제 브라우저 실행 성공까지 확인한다. 정적 검사만 했으면 화면 검증 완료가 아니다. `--no-render`로 전체 통과를 대신하지 않는다.
- 웹 검색·원문 접근은 별도 능력이다. 현재 도구 목록과 작은 시험으로 확인하고 `research.md`의 A/B/C/D 경로를 고른다. 파일 생성 가능과 사실 조사 가능을 혼동하지 않는다.

## Claude Code 등 로컬 파일·명령 실행 에이전트

스킬 자동 검색 위치는 현재 설치된 제품의 안내를 따른다. 자동 등록 없이도 가족형 배포본의 `edu-deck/SKILL.md`를 직접 읽게 하고 시작할 수 있다. 세 폴더를 따로 이동하거나 공통 자산을 복제하지 않는다. Claude Code용으로 사용자 설정의 `~/.claude/skills/`를 사용하는 경우에도 세 폴더를 함께 유지하고 실제 발견 여부를 확인한다. 이는 설치 예시이지 다른 실행기의 필수 경로가 아니다.

## Claude 웹·데스크톱 계열

현재 계정·화면에서 사용자 스킬 ZIP 등록을 제공하면 단일 루트 배포본을 후보로 사용한다. ZIP 허용 여부·파일 크기 제한·실행 도구·지원 구조는 해당 환경에서 확인해야 한다. 일반 첨부와 스킬 등록은 서로 다르며, 업로드만으로 등록 또는 Python·브라우저 실행을 보장하지 않는다.

등록 기능이 없더라도 파일 추출·읽기가 가능한 작업 환경에서는 단일 루트의 `edu-deck/SKILL.md`를 읽도록 요청할 수 있다. 실행할 수 없는 단계는 중단하고 로컬 실행 환경으로 넘긴다. 실제 제품 업로드·등록은 이 배포의 로컬 검증 범위에 포함되지 않는다.

## ChatGPT

이 ZIP을 ChatGPT 전용 플러그인이나 자동 설치 가능한 스킬로 간주하지 않는다. 파일 첨부·압축 해제·Python 실행·결과 다운로드 가능 여부는 사용 중인 환경에서 먼저 확인한다. 가능하면 단일 루트 배포본을 작업 자료로 제공하고 `edu-deck/SKILL.md`부터 읽도록 요청한다.

Python으로 조립할 수 있어도 Playwright·브라우저 또는 네트워크가 없을 수 있다. 생성·정적 검사·화면 검사·출처 대조를 구분해 보고한다. 파일 접근이나 실행이 없으면 구성안과 실행 안내까지만 제공하며, 만든 적 없는 HTML이나 검사 통과를 주장하지 않는다.

## 그 밖의 에이전트

고유 명령·전용 메모리·서브에이전트가 필수인 작업은 없다. 파일 읽기·작성, Python 실행, 브라우저 검사, 조사 수단을 각 환경의 실제 도구에 대응한다. 없는 도구 이름을 지어내지 않는다. 명령은 셸 문법과 Python 실행 파일만 환경에 맞게 조정하고, 원본 스킬의 승인 지점과 검사 기준은 유지한다.
