# edu-deck: 교육 덱 진입 · 판별 (라우터)

교육 자료 요청을 받으면 먼저 규모를 판별해 알맞은 하위 스킬로 보낸다. 이 스킬은 판별만 한다. 조사·구성·제작 절차는 하위 스킬에 있다.

## 판별 절차

0. **먼저 대상 확인.** edu-deck 은 "듣는 사람이 무언가를 배우는 교육·훈련 자료"를 만든다. 제안서·입찰·피치덱·IR·전략 보고처럼 설득·권고가 목적인 덱은 대상 밖이다 — 이 스킬로 만들지 말고, consulting-deck 스킬(컨설팅 덱 전용)이 같이 설치돼 있으면 그 경로로 안내하고, 없으면 사용자에게 알린다. 산출물이 파워포인트 파일인 요청("PPT로 만들어", ".pptx 로 줘")도 HTML 덱의 대상 밖이다 — 이웃 `ppt-master` 스킬(`../ppt-master/SKILL.md`, 네이티브 DrawingML PPTX — 슬라이드 마스터·도형·데이터 차트·표가 모두 편집 가능하게 생성됨)이 설치돼 있으면 그 경로로 안내하고, 없으면 알린다. 다만 "기술이전 교육"·"운영 매뉴얼 교육"·"사내 워크숍"처럼 배우는 사람이 있으면 교육 자료다(대상). 애매하면 1번부터 신호를 본 뒤 한 번 묻는다.
1. **요청 신호를 읽는다.**
   - 단일 발행 신호: 주제 하나("폭염 안전"), 산출물 하나("파일 하나", "한 번 끝내는"), 날짜·시간이 한 번("45분 교육").
   - 시리즈 신호: "시리즈", "여러 편", "N편", "묶음", "지속·정기 교육", "진도", "다 본 편", "허브/포털", 편 제목이 여러 개 나열됨.
2. **판정**
   - 단일 발행 → **edu-deck-solo** 경로.
   - 시리즈(2편 이상 + 진도·허브·통합 용어집 등 묶음 기능) → **edu-deck-series** 경로.
   - 시리즈 같지만 아직 규모를 못 정한 경우("주제가 커서 어떻게 나눌지 모르겠다")에도 시리즈 경로다 — 편 나누기는 edu-deck-series 가 구성안에서 다룬다.
3. **애매하면 묻는다(한 번, 간단하게).** 둘 다 가능할 때는 이렇게:
   > "한 번에 다 담은 파일 하나로 만들까요, 아니면 여러 편 시리즈(진도 관리·허브 화면 포함)로 나눌까요? 시리즈는 편마다 별도 학습 흐름이 생깁니다."
   답을 받으면 그 경로를 탄다. 답이 없으면 단일 발행(solo)로 진행하고 보고에 판별 근거를 남긴다.

## 경로 타기

- **edu-deck-solo**: 이웃 스킬 `edu-deck-solo/SKILL.md` 를 읽고 그 절차를 처음부터 따른다(요청 정리 → 조사 → 구성 → 제작 → 검사 → 보고). 조각·스타일·검사 스크립트·공통 문서는 이 스킬(edu-deck) 폴더의 `shared/` 에 들어 있다 — 하위 스킬의 안내(`〈base〉`)를 따른다. 하위 스킬에게 사용자 승인·권한이 그대로 이어진다.
- **edu-deck-series**: 같은 방식으로 `edu-deck-series/SKILL.md` 를 읽고 따른다. 공통 자산은 마찬가지로 `shared/` 를 쓴다. **edu-deck-series 가 설치되어 있지 않으면** 사용자에게 "시리즈용 스킬이 아직 없다"고 알리고 — 단일 편으로 시작할지(edu-deck-solo), 시리즈 스킬을 먼저 만들지 확인한다. 몰래 solo로 진행하고 시리즈라고 보고하지 않는다.
- **책 양식(bookstyle-html)**: 요청이 `책 양식`·`플립북`·`인사이트북`(600×820 쪽 펼침 넘김 단일 HTML)이면 이 라우터의 덱 경로를 타지 않고 `../bookstyle-html/SKILL.md` 를 사용한다. 판면·뷰어·검사기가 다르므로 edu-deck 의 팩/legacy 경로·`check_deck.py` 를 섞지 않는다.

## 새 덱의 공통 저작 경로

규모를 판별한 뒤 하위 스킬이 새 덱·새 시리즈 편을 만든다. 만들기 전에 아래 "경로 결정"으로 팩 경로와 legacy 경로 중 하나를 정한다(기본값 없음).

## 경로 결정 (새 덱·새 시리즈를 시작할 때 한 번, 덱 단위)

덱은 **팩 경로** 또는 **legacy 경로** 중 하나로 만든다. 한 덱에 둘을 섞을 수 없다(팩 덱에 legacy 조각을 넣으면 `check_deck.py` 가 ERROR 로 실패한다). 그래서 저작을 시작하기 전에 정하고, 시리즈는 시리즈 단위로 한 번 정한다. 어느 쪽도 "기본값"이 아니다. 에이전트가 요청을 보고 판단한다.

1. **강제 조건**(판단하지 않는다)
   - 기존 덱 편집: `deck.json` 에 `resource_pack` 이 있으면 팩, 없으면 legacy.
   - 사용자가 경로나 디자인을 지정: "기존 형식"·"legacy" 는 legacy, 팩 디자인 이름이나 "팩"은 팩.
   - 팩에 없는 조각이 꼭 필요: 숫자 증거 띠(`stat-strip`)·실물 화면 인용(`screen-cite`)은 legacy.
2. **판단 신호**(강제 조건이 없을 때. 측정한 기준이 아니라 판단 기준이다)
   - 팩 쪽: 청중이 직접 해 보는 활동·판단·토론이 성과의 중심이다(따라하기·진단·탐구·토론·프로젝트·사례 판단). 비교적 짧다(대략 10~20장). 디자인을 시안으로 골라야 한다.
   - legacy 쪽: 개념·규정·절차를 설명하고 퀴즈로 확인하는 긴 덱이다(대략 30장 이상). 표·도식·퀴즈 유형이 여러 가지 필요하다. 사용자가 기존 결과물과 같은 형식을 원한다.
3. **결정 규칙**
   - 신호가 한쪽으로 분명하면 **스스로 정하고 진행**한다. brief 와 최종 보고에 `경로: 팩 (근거: …)` 한 줄을 남긴다.
   - 신호가 섞이거나 약하면 **사용자에게 한 번 묻는다.** 두 경로를 각각 한 줄로 설명하고 추천 하나와 이유를 붙인다. 답이 올 때까지 저작을 시작하지 않는다.
   - 위임 실행처럼 물을 수 없으면 추천 경로로 진행하고, brief 와 최종 보고의 "확인 필요"에 `경로를 추천으로 정함(근거: …)` 을 남긴다. 신호가 비슷하면 팩을 추천한다(디자인·흐름 조합이 더 넓다).
4. 경로가 정해지면 해당 라우터를 돌린다: 팩은 `shared/scripts/pack_router.py`(디자인 8·흐름 8 후보 3종), legacy 는 `shared/scripts/tone_router.py`(테마 9·표지 16·arc 6). 라우터 점수는 후보를 좁히는 휴리스틱이므로 청중·수행 행동·평가 증거로 확인한다.
5. 저작 중에 경로를 바꾸면 이미 쓴 장을 새 경로로 다시 써야 한다. 바꿔야 하는 이유가 생기면 진행을 멈추고 사용자에게 알린다.

### 자유 모드와 가이드 모드

기본은 **자유 모드**다. 조각·팩 템플릿·arc 메뉴·아키타입 표는 참고 예시이고 지시가 아니다 — 에이전트가 직접 설계해도 되며, 스킬은 예시 경로·샘플·재료·도구만 준다. 재료 사용 4방식·작업 덱 수정 권한·품질 판단 기준은 `shared/references/authoring.md` 한 곳에 있다. 검사기는 안전 가드(깨짐·접근성·계약)만 ERROR 로 막고, 취향 규칙은 INFO 다(`check_deck.py --style` 에서 WARN 상세). 모델 이름으로 분기하지 않는다. **가이드 모드**로 가는 경로는 세 가지뿐이다:

1. 자동 폴백: 같은 장의 같은 고침이 3회 반복되면 고침 재시도 대신 원인 분석부터 한다(authoring.md 7절) — 가이드 문서(`composition.md`·`layouts.md`·`design.md` 판단 기준·카탈로그 조각)로의 전환은 그 장의 해결 수단 중 하나다. 실패 횟수만으로 덱 전체를 고정 형식으로 바꾸지 않는다.
2. 사용자·지시문이 "가이드 모드"라고 지정하면 처음부터 가이드 문서를 따른다.
3. 위임자가 약한 모델이라고 판단해 위임문에 "가이드 모드"를 넣으면 따른다.

안전 가드는 두 모드 모두에 적용된다. `data-archetype` 가 없는 장도 허용된다 — 엔진이 자동 배정한다(statement, `.chk` 가 있으면 check).

**팩 경로**: 같은 모양이 반복되지 않도록 디자인 8종과 학습 흐름 8종에서 주제에 맞는 조합을 고른다. `pack_router.py` 의 후보 3종·추천·흐름(최근 쓴 디자인은 `--recent` 로 감점)을 시작점으로 삼고, **에이전트가 청중·수행 행동·평가 증거로 스스로 확정한다** — 시안 3종 비교(`preview_pack.py`)는 사용자가 비교·승인을 요청했을 때나 시각 비교가 필요하다고 판단할 때 쓰는 선택적 기법이다(solo 3.5절·`shared/references/authoring.md` 5절). 선택은 `deck.json.resource_pack` 에 명시하며 보조활동은 주흐름과 다른 흐름을 중복 없이 최대 2종만 고른다. 팩 덱도 공통 아이콘 묶음과 개념 SVG 도식은 쓸 수 있으나 legacy 배치 클래스·조각·CSS 는 섞지 않는다.

**legacy 경로**: `shared/references/composition.md` 의 유형표·줄거리, `layouts.md` 의 아키타입·`assets/snippets/`·공통 아이콘(`icons.md`)·개념 SVG 도식(`diagrams.md`)으로 저작하고, 장의 배치·강조·밀도·색 판단은 `shared/references/design.md` 의 기준을 따른다. 덱마다 얼굴이 달라지게 `deck.json` 의 `theme`(17종, 기본 classic)·`arc`(6종, 기본 standard)를 `python3 shared/scripts/tone_router.py --title … --outcomes … --audience …` 의 추천으로 고른다. 표지는 `shared/references/authoring.md` 3절의 재료 사용 4방식(그대로·변형·조합·새로 설계) 중 내용에 맞는 방식으로 만든다 — 카탈로그 변형 16종(`01-cover*.html`)은 출발점 재료이지 실패 폴백이 아니다. 방식과 무관하게 표지 계약은 `shared/references/layouts.md` "표지 직접 설계 계약"을 따른다. 모두 생략하면 기존 결과 그대로다.

새 팩 생성기는 저작용 뼈대이지 검증된 강의가 아니다. 실제 조사 내용·110~450자 발표자 노트와 같은 디자인 안의 다양한 배치 변형을 작성하고 하위 스킬의 검사를 거친다. 팩 경로는 legacy 포팅 도구나 원래 Downloads HTML을 필요로 하지 않는다.

## 공통 시각·모션 계약

하위 스킬은 `shared/references/DESIGN_TOKENS.md`와 `MOTION_LIBRARY.md`를 적용합니다. 차분한 바탕과 장마다 의미 있는 임팩트 하나를 조합합니다. 비유·예시는 도식·일러스트·장면 모형을 반드시 짝지으며(개념 SVG 도식 문법은 `shared/references/diagrams.md`), 모션은 조각이 아니라 공통 셸이 소유합니다. 인라인 SVG를 권장하고 필요한 라스터는 덱당 1.5MB 이내 base64만 허용합니다. Pretendard 원본과 라이선스는 HTML에 임베드합니다. 외부 로딩은 금지하며 자습·인쇄·움직임 줄이기에서는 현재 의미 단계가 정적으로 완결되어야 합니다.

화면 크기별 배치·조작·검사는 [공통 반응형 계약](shared/references/responsive.md)을 따릅니다. 좁은 화면에서는 원본 배치를 축소한 세로 읽기·터치 버튼·탭으로 여는 크게 보기를 제공하고, 데스크톱 발표·인쇄는 1920×1080을 유지합니다. 기존 결과물은 재조립해야 반영됩니다.

뷰어 기능과 키(검색 Ctrl+K·/ · 목차 O · 발표 타이머 T·R·V)는 [공통 클래스 사전](shared/references/classes.md)의 "뷰어 도구" 절과 [발표 덱(talk 모드)](shared/references/talk.md)을 따릅니다.

## 판별 기록

경로를 정했으면 최종 보고에 한 줄 남긴다: "판별: 단일 발행(신호: …) → edu-deck-solo" 또는 "판별: 시리즈(신호: …) → edu-deck-series / 사용자 확인".

덱 경로도 최종 보고에 한 줄 남긴다: "경로: 팩 (근거: …)" 또는 "경로: legacy (근거: …)". 사용자에게 물었으면 "사용자 확인", 물을 수 없어 추천으로 진행했으면 "추천으로 진행"을 덧붙인다.

## 하위 스킬 안내

| 스킬 | 결과물 | 어울릴 때 |
|---|---|---|
| edu-deck-solo | 반응형 단일 HTML 덱 한 파일(발표·인쇄 1920×1080)(단계 등장·발표자 노트·퀴즈·확인 문제·자습 모드) | 한 주제, 한 번 발행, 15~60분 교육 |
| edu-deck-series | 시리즈 포털 HTML(허브·편 진도·자습·통합 용어집 + 편마다 덱) | 여러 편, 정기·지속 교육, 학습 진도 관리 |

두 스킬 모두 결과물은 외부 파일 없이 어디서나 열리는 단일 HTML 이다. 공통 자산(팩 catalog·flows·템플릿·스타일, 교육 실행 셸, legacy 조각·아이콘, 문서·조립/검사 스크립트)은 이 스킬 폴더의 `shared/` 한 곳에 있고 하위 스킬이 함께 쓴다(중복 없음). 팩 덱은 독립 시각 자산을 쓰되 기존 퀴즈·자습·시리즈 계약과 공통 아이콘·개념 SVG 도식을 함께 쓴다. 기존 크레파스 속성은 공통 모션 엔진의 캔버스 크레파스 표시로 연결한다.

두 경로 모두 최종 검사 전에 말투 교정 절차(`shared/references/copyedit.md`, solo 5.5단계)를 반드시 거친다 — 교정 없이 완료 보고하지 않는다.
