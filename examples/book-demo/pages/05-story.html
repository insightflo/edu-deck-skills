구성 사례 · 개발 생산성 팀

리뷰 에이전트가
12개 저장소를 읽을 수 있었다

야간에 도는 코드 리뷰 에이전트. 리뷰 품질은 좋았고, 아무도 권한을 다시 보지 않았다.
PROBLEM · 이런 문제가초기에 개인 토큰 하나를 그대로 붙였다. 그 토큰은 팀이 쓰는 12개 저장소와 패키지 레지스트리까지 닿았고, 무엇을 읽었는지 남는 기록은 없었다.
SOLUTION · 이렇게에이전트 전용 신원을 만들고, 저장소 2곳의 읽기와 코멘트 작성만 남겼다. 배포·머지·비밀값 접근은 실행 전 승인 단계로 옮겼다.
KEY FEATURES · 바꾼 것
1도구 호출마다 신원·도구·대상을 기록
2범위 밖 요청은 실패가 아니라 승인 요청으로
3야간 결과는 아침에 사람이 한 번 확인
POINT권한을 줄이는 일은 성능을 깎는 일이 아니라 사고의 반경을 줄이는 일입니다.
구성 예시: 실제 조직·수치가 아닌 설명용 시나리오5
