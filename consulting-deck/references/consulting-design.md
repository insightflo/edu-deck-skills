# 컨설팅 시각 설계 (consulting-design)

## 1. 시각 방향 4종 — 목적이 고른다, 테마에 끼워맞추지 않는다

| 방향 | 언제 | 특징 | 톤 |
|---|---|---|---|
| **Executive Minimal** | 보드·경영진 보고, 결정 요청 | 밝은 배경, 주장형 제목, 핵심 수치 강조, 여백으로 위계 | 절제·신뢰 |
| **Analytical Dense** | 조사 보고, 실사, 데이터 리뷰 | 고밀도·정돈된 차트, 직접 라벨, 방법론 풋노트 — 전시가 캔버스 55~75% | 정밀·투명 |
| **Strategy Editorial** | 사고 리더십, 비전 제안 | 메시지 중심 편집 디자인, 과감한 비율과 대조 | 관점·기억 |
| **Tech Transformation** | IT 전환·아키텍처 프로그램 | 기술 아키텍처–비즈니스 영향–로드맵의 연결 강조, Architecture Kit 결합 | 구조·추진력 |

- 방향은 brief에서 정하고 덱 전체에 하나만 쓴다. 방향마다 consult.css 변형(토큰만 다른)으로 구현한다 — 장 배치를 방향이 바꾸게 하지 않는다.
- 조형 분리는 색뿐 아니라 토큰으로 둔다 — `--c-radius`(Executive~0·Tech 헤어라인 활용)와 `--c-num-font`(Executive=에디토리얼 세리프 수치, Tech=ui-monospace+tabular-nums)가 방향마다 다른 값을 갖는다(consult.css 1절).
- 애매하면 Executive Minimal로 시작하고 내용 밀도가 방향을 바꿀 만큼 heavy해지면(증거 장 비중 60%+) Analytical Dense로 간다. 전환은 덱 전체를 다시 본다.

## 2. 밀도 — 발표자가 있나, 혼자 읽나

| | Speaker-led | Reading-first |
|---|---|---|
| 전제 | 발표자가 설명한다 | 받는 사람이 혼자 읽는다(이메일 회람·보고 파일) |
| 장 구성 | 큰 주장 1 + 차트 1 + 최소 텍스트 | 주장 + 근거 + 주석 + 출처가 장 안에서 완결 |
| 글자량 | 장당 본문 3문장 이하 | 밀도 허용, 단 계층(제목→소제목→본문→주석)은 유지 |
| 노트 | 발표 근거를 노트에 | 노트에 근거 요약+링크 |

- **애매한 중간 금지.** 발표와 회독이 둘 다 필요하면 장을 나누거나 논증을 예리하게 하고, 그래도 안 맞을 때만 글자 크기를 조정한다 — 축소가 먼저가 아니다.
- 이 축은 방향(4종)·서사 모드와 독립이다: 조사 중심 덱(증거 장 60~80%)인지 서사 중심 덱(프레임워크·로드맵이 서사를 더 담음, 35~60%)인지와 별개로 밀도를 정한다.

## 3. 타이포·위계

- 크기 질서(1920×1080 기준): 표지 주장 > 장 주장형 제목 > 핵심 수치 > 소제목 > 본문 > 차트 라벨 > 주석 > 출처. 출처가 가장 작아도 18px 미만으로 내려가지 않는다(가독 하한).
- 굵기는 3종 이내(예: 700 주장 / 600 소제목 / 400 본문). 색으로 위계를 보태되 15색 역할 토큰 안에서.
- 핵심 수치는 단위 없이 크게, 단위·기간은 작게 붙인다("**2.3배** (3년, 업계 평균 대비)").
- 글이 넘치면 분할·요약이 먼저, 글자 축소가 마지막이다(`<base>/references/design.md` 공통 원칙과 같다).

## 4. 색 역할 — 15색 토큰 위의 컨설팅 규칙

- **accent(초점) 1종**이 판단·권고·강조를 담고, **blue(근거)**가 비교 데이터를 담는다 — 초점과 근거가 같은 계열색이면 "어디가 결론인지"가 흐려진다. PoC에서 확립한 역할 분리다.
- 장식 색은 없다. 화면의 색은 역할(초점·근거·맥락·긍정·부정·축) 중 하나를 가져야 하고, 없으면 무채색 계열이다.
- semantic 긍정/부정 색은 실제 호전/악화에만. 덱 전체에서 같은 색은 같은 의미여야 한다(`<base>/references/design.md` 일관성 규칙).

## 5. 펌 패턴 9종 — 우리 문법으로 번역해 쓴다

공개 보고서에서 반복 관측한 패턴(reference-sources.md)과 그 구현:

| 펌 패턴 | 우리 구현 |
|---|---|
| 제목은 주장이다 | 모든 장 제목 주장형(storyline.md §6). 차트 장도 예외 없음 |
| 요약 먼저(At a Glance/Key Takeaways) | 표지 다음 Exec Summary — 3불릿(c-glance), 각 불릿=주장+수치 |
| 숫자가 문장을 이긴다 | 주장마다 비율+절대치+기준시점 병치("44% → 904조 원, 2025년 기준") |
| 전환 수사의 리듬 | '개선 → 그러나' 쌍을 장 2개 또는 한 장 2단계로(data-step) |
| 근거의 투명한 이격 | 차트마다 Notes(방법론)+Source 블록(c-note·c-src), 표본을 주장 직전에 |
| 명명된 세그먼트·번호 프레임워크 | 세그먼트에 이름+비율+성격을 붙여 카드 순차 등장(예: 선도 15%·실용 70%·후행 15%) |
| 행동으로 닫는다 | 마지막 장 명령형 권고 3~5(c-do) + 결정 요청 |
| 논증과 차트의 면적 분리 | 한 장에 논증+차트를 우겨넣지 않는다 — 차트가 주인공이면 텍스트는 제목+주석만 |
| 요약/상세 계층화 | Exec Summary(결론) ↔ 본부(근거) ↔ 부록(원본) 3층. 시리즈·허브 구조와 동일한 원리 |

## 6. 금지 패턴

- 네온 그라디언트·전체 어두운 배경·글래스모피즘·앱 대시보드풍 카드 벽 — 컨설팅 덱은 문서지 앱이 아니다.
- 특정 펌의 레이아웃·로고·차트 스타일 복제(reference-sources.md 경계). 패턴은 번역해서 쓴다(§5).
- 의미 없는 아이콘 장식(아이콘이 분석을 대신하는 것), 이모지, 손글씨 일러스트.
- 검사기 통과용 장치(빈 도식·이름뿐인 클래스) — `<base>/references/authoring.md` §6과 같다.

## 7. consult.css — 덱 로컬 테마

- 테마는 **덱 작업 폴더의 src/*.css**로 만든다. `consulting-deck/assets/consult.css`(4방향 토큰 세트)을 복사해 쓰고, `.slide.consult` 스코프 안에서 값을 조정한다. **공유 파일(edu-deck/shared/)은 수정하지 않는다** — 기존 교육 덱 무영향 원칙.
- consult.css가 제공하는 역할 클래스: `c-glance`(At-a-Glance 3불릿, 상단 잉크 룰 칼럼형) · `c-metrics`(핵심 수치 띠) · `c-sonw`(So What/Now What) · `c-table`(평가표, `rec` 행 강조) · `c-do`(권고 블록) · `c-rule-rows`(헤어라인 행 목록 — 라벨 칼럼+본문 칼럼, 카드 그리드 대안) · `c-sidecar`(차트 68%+시사점 칼럼 32% — chart_gen `canvas:"sidecar"` 출력) · `c-note`·`c-src`(방법론·출처) · `s-syn`(가상 데이터 표기). chart_gen 조각이 방출하는 클래스는 덱 CSS가 반드시 정의한다(schema.md 출력 계약).
- 방향 전환은 토큰 값(색·그림자·반경)만 바꾼다 — 레이아웃·클래스 구조는 그대로. legacy 테마 9종과 섞지 않는다.
