# 컨설팅 덱 심미 리뷰 — 특화 계약 (deck-design-critic)

> **로드 시점**: 컨설팅 덱 완성 직후(게이트 통과 뒤)와 "미학이 아니다"류 피드백을 받았을 때.
> **공통 계약**: 절차 6단계·9항목 질문표·Blocker/Major/Minor 등급·캡처 도구·크리틱 에이전트 호출 규칙은
> `<base>/references/design-critique.md`가 소유한다 — 이 문서는 그 위의 **컨설팅 특화**만 남긴다.
> 컨설팅 덱에서 9항목 중 특히 **차트·도식 전달력**(시사점)과 **정체성**(펌과 구분)이 결정적이다.

## 1. 컨설팅 확장 절차 (공통 6단계 위에 얹는다)

1. **캡처·전체 보기** — 공통 §4 도구로 전 장 최종 상태(`deckGo(i, 99)`) 캡처, 축소본으로
   리듬·배치 다양성·실루엣 반복을 먼저 본다.
2. **9항목 진단 + 펌 대비** (아래 §2) — 장 단위가 아니라 덱 단위 + 대표 장 심층.
   기술 결함(겹침·잘림·대비 수치)은 심미와 분리해 별도 표기.
3. **진단 언어화** — "더 세련되게" 금지. 어떤 장·어느 요소가·왜 어색한지·어떻게 바꾸는지 네 단위로.
4. **우선순위 5** — 영향 큰 문제만. 정체성·차트 시사점·위계 순으로 가중한다.
5. **방향 시안 2~3안** (아래 §3) — 콘텐츠·데이터·논리는 유지한 채 시각 방향만 갈라 올리고 고르게 한다.
6. **전후 비교·재평가** — 개선 후 같은 관점으로 재검수, before/after 캡처를 남긴다.

## 2. 펌 대비 — Tier-1 언어화

- McKinsey·BCG·Bain 공개 자료(reports 등)와 나란히 놓고 차이를 **언어**로 만든다:
  무엇이 우리 덱의 결정적 시사점이고, 펌 자료가 그걸 어떤 조형(헤어라인·측면 칼럼·숫자 스케일)으로
  지지하는가. 로고·레이아웃 복제 금지 — 비교는 관점 확보용이다.
- 크리틱 브리프에 펌 대비 관점을 명시해 넣는다(공통 §5 호출 규칙은 그대로).

## 3. 방향 시안 2~3안 — 선택받는 개선

- 대표 슬라이드 2~3장(표지·핵심 차트장·권고장)에 서로 구별되는 디자인 방향을 올린다.
  예: 임원 미니멀 강화 / 분석 사이드카 계승 / 에디토리얼 대비.
- 각 안은 토큰·구조 클래스 수준에서 실현 가능해야 한다(구현 근거 없는 분위기만 제시 금지).
- 사용자가 고르게 한다 — 사용자가 없는 자율 실행에서는 근거를 남기고 한 안을 선택해 입증한다.

## 4. 반대 금지 (컨설팅 특화)

- 정렬·간격 손보기로 끝내는 단순 polish로 "심미 리뷰 반영"이라 주장하지 않는다 — 필요하면
  조형 구조·레이아웃 자체를 재설계한다.
- 이유 없이 전 장을 화려하게 만들지 않는다. 펌 스타일을 모방해 우리 시각 문법을 지우지 않는다.
- 자동 검사(check_deck·check_consulting) 통과를 심미 품질의 증거로 제시하지 않는다.

## 5. 출처 (개념 참조 — 코드 복사 없음)

  디자인 어휘와 "리뷰와 기술 검사 분리" 원칙.
- **designer-skills / design-review** (julianoczkowski/designer-skills, Apache-2.0) — 실제 화면
  캡처 필수 검증 절차(코드만 읽고 평가 금지).
- **better-web-ui** (aladicf, 로컬 설치 스킬 — critique·hierarchy·data-viz 등) — 세분화 진단 렌즈.
- 웹 UI용 스킬 원칙을 **슬라이드·스토리텔링·발표 위계**로 보완해 재작성했다(본 문서가 주체).
