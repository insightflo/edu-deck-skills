# 덱 심미 리뷰 — 독립 아트 디렉터 계약 (deck-design-critic)

> **로드 시점**: 컨설팅 덱 완성 직후(게이트 통과 뒤)와 "미학이 아니다"류 피드백을 받았을 때.
> 자동 검사(check_deck·check_consulting)는 **깨짐**을 잡고 **심미 품질**을 증명하지 않는다.
> 저작 에이전트는 자기 결과물을 스스로 칭찬한다 — 평가는 **시각 판단 기능이 있는 별도 에이전트**(이
> 환경: agy / gemini-4-argon, 호출 규칙은 아래)가 실제 화면 캡처를 보고 수행한다.

## 1. 절차 (완성 → 비평 → 언어화 → 방향 비교 → 선택 → 개선·재평가)

1. **캡처** — `checks/capture_deck.py <덱.html> <출력폴더>` 로 전 장 1920×1080 최종 상태 PNG.
   최종 상태란 `deckGo(i, 99)`(모션 완결)를 뜻한다 — 모션 중간 프레임은 결함으로 오탐된다(실측 교훈).
2. **전체 보기** — 축소본 그리드로 리듬·배치 다양성·실루엣 반복을 먼저 본다.
3. **7관점 질문** (아래 표) — 장 단위가 아니라 덱 단위 + 대표 장 심층.
4. **펌 대비** — McKinsey·BCG·Bain 공개 자료(reports 등)와 나란히 놓고 차이를 언어화한다.
   로고·레이아웃 복제 금지 — 비교는 관점 확보용이다.
5. **진단 언어화** — "더 세련되게" 금지. **어떤 장·어느 요소가·왜 어색한지·어떻게 바꾸는지** 네 단위로.
6. **우선순위 5** — 영향 큰 문제만. 기술 결함(겹침·잘림·대비 실패)은 심미와 분리해 별도 표기.
7. **방향 시안 2~3** — 대표 슬라이드 2~3장에 서로 구별되는 디자인 방향(예: 임원 미니멀 강화 /
   ztd 트랙 계승 / 에디토리얼)을 올리고 사용자가 고르게 한다. 콘텐츠·데이터·논리는 유지.
8. **전후 비교·재평가** — 개선 후 같은 관점으로 재검수, before/after 캡처를 남긴다.

## 2. 7관점 질문표

| 관점 | 질문 |
|---|---|
| 시각적 위계 | 3초 안에 이 장의 핵심 메시지가 눈에 들어오는가? |
| 레이아웃 | 모든 장이 비슷한 카드·박스 구조를 반복하지 않는가? |
| 타이포그래피 | 제목·숫자·본문·주석의 대비와 리듬이 살아 있는가? |
| 차트 디자인 | 범용 차트가 아니라 분석 결과와 시사점이 보이는가? |
| 공간 활용 | 의도적 여백인가, 화면을 채우지 못한 빈 공간인가? |
| 디자인 정체성 | 다른 AI가 만든 덱과 구분되는 고유한 스타일이 있는가? |
| 모션 | 결론 이해를 돕는가, 단순 장식인가? |

## 3. 등급 — 기술 결함과 심미 문제를 분리한다

- **기술 결함**(자동 검사·DOM 검증 소관): 글자 겹침·넘침·대비 수치 미달·렌더 오류.
  → 코드 수정 의무. 심미 리뷰에 섞지 않는다.
- **심미 치명**: 핵심 메시지가 3초 안에 안 보이는 장, 정체성 부재(AI 범용 스타일), 차트가
  시사점을 안 보여주는 것 → 방향 수립 전까지 납품 중단 권고.
- **심미 권고**: 위계·리듬·여백 개선 → 다음 패스 반영.
- **심미 취향**: 참고.

## 4. 시각 판단 에이전트 호출 (이 환경 계약)

```
hc run --name <이름> --bg agy --dangerously-skip-permissions   # 권한 프롬프트 방지 옵션 필수
hc send <주소> '<브리프 — 캡처 폴더·7관점·보고 파일 경로·완료 한 줄>'
```

- 브리프에: 캡처 폴더(가능하면 워크스페이스 안), 7관점 질문표, 펌 대비 관점, 우선순위 5 요구,
  보고 파일 경로, git 금지. 보고 형식: 판정(대상별)·치명/권고/취향(장 번호+요소+현상+제안)·결론.
- 저작 에이전트는 보고를 받아 **치명→권고** 순으로 반영하고, 자동 검사 재실시 후 재평가를 요청한다.

## 5. 반대 금지

- 정렬·간격·색상 손보기로 끝내는 단순 Polish로 "심미 리뷰 반영"이라 주장하지 않는다 — 필요하면
  조형 구조·레이아웃 자체를 재설계한다.
- 이유 없이 전 장을 화려하게 만들지 않는다.
- 자동 검사 통과를 심미 품질의 증거로 제시하지 않는다.

## 6. 출처 (개념 참조 — 코드 복사 없음)

  디자인 어휘와 "리뷰와 기술 검사 분리" 원칙.
- **designer-skills / design-review** (julianoczkowski/designer-skills, Apache-2.0) — 실제 화면
  캡처 필수 검증 절차(코드만 읽고 평가 금지).
- **better-web-ui** (aladicf, 로컬 설치 스킬 — critique·hierarchy·data-viz 등) — 세분화 진단 렌즈.
- 웹 UI용 스킬 원칙을 **슬라이드·스토리텔링·발표 위계**로 보완해 재작성했다(본 문서가 주체).
