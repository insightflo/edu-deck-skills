> **소유 영역**: 컨설팅 덱의 품질 게이트 — 논리·데이터·시각·실행 네 영역의 기준, 자동 검사와 사람 승인의 구분. 실행 계약·접근성·렌더 검사는 `<base>/scripts/check_deck.py`가 소유한다. 검사와 품질이 다르다는 공통 원칙은 `<base>/references/authoring.md` §6이다.
> **로드 시점**: 작업 순서 6단계(검사)와 7단계(보고) — 게이트를 돌리고 결과를 해석할 때.

# 품질 게이트 (quality-gates)

## 0. 발견 분류 — 세 등급

| 등급 | 뜻 | 처리 |
|---|---|---|
| **blocker** | 납품 불가 — 근거 없는 수치, 합계 불일치, 깨진 렌더 | 고칠 때까지 납품하지 않는다 |
| **warning** | 명시하면 납품 가능 — stale 출처, 밀도 초과 경향 | 화면 표기·보고로 공개한다 |
| **advisory** | 사람 판단 — 리듬·어조·기억 가능성 | 저자가 판단하고 근거를 보고에 남긴다 |

**의미 문제를 기계 레이아웃 패치로 자동 수정하지 않는다.** 자동 검사는 코드가 볼 수 있는 것만 검사하고, 의미(논리·설득력)는 사람이 본다.

## 1. 논리 게이트 — 덱이 하나의 논증인가

- Exec Summary의 주장이 본문 장들과 일치하는가(본문을 고치면 Exec Summary도 고쳤는가).
- **제목 연쇄**: 제목만 순서대로 읽으면 짧은 경영 메모처럼 읽히는가. 인접 중복 결론·진단 없는 행동(비약)·부록 이야기의 본문 끼어듦이 없는가.
- 주장마다 대응하는 근거 장이 있고, 근거 없는 주장은 가설 라벨 또는 삭제로 처리했는가.
- 권고·실행 과제가 **진단된 원인을 실제로 다루는가** — 진단과 무관한 "모범사례 나열"이 아닌가.
- 마지막 장이 행동으로 닫히는가(결정 요청 포함).
- 자동 검사 영역: `check_consulting.py`가 Exec Summary↔본문 수치·문장 대응, 장 제목 구조(주장형 여부 신호)를 검사한다. 나머지는 사람 판단 — 보고에 결론으로 남긴다.

## 2. 데이터 게이트 — 수치가 진짜인가

- 차트 값 ↔ charts 모델 ↔ evidence.json 원장이 일치하는가(화면 어디에도 모델 밖 수치가 없는가).
- 합계·비율·증감률: 구성합=총합, 워터폴 시작+드라이버=끝(expectTotal), CAGR·증감의 기준점.
- 단위·기준일·기간이 장마다 명시돼 있고 통일돼 있는가. %의 분모는?
- 가정/추정/전망/실적 구분 표기가 화면에 남아 있는가. synthetic은 "가상 데이터" 표기와 1:1인가.
- 축 왜곡 방지: 축 생략 표식·실측치 라벨·0 기준 필요성(evidence.md §6 체크리스트 전체).
- 자동: chart_gen(모델 검증)·check_consulting(원장 대조)·regen --check(재생성). 사람: 반올림 자릿수 통일, 해석 문장의 수치 인용.

## 3. 시각 게이트 — 위계가 설득하나

- 정보 위계: 장 안에서 눈이 주장 → 증거 → 근거 순으로 움직이는가. 초점(accent)이 장마다 1개인가.
- 공간 활용: 차트가 주인공인 장에서 차트가 캔버스를 지배하는가(Analytical Dense 55~75%). 여백이 의도적인가.
- 라벨 겹침·잘림·글자 크기(출처 포함 최소 기준)·주목해야 할 데이터의 강조 — **1920×1080 캡처를 직접 보고 판단한다.** 기하 무겹침·페이지에러는 check_deck 렌더 검사로.
- 일관성: 같은 색=같은 의미, 같은 종류 장=같은 골격, 배치 다양성(≥5/7 유형, 동일 실루엣 3연속 금지).
- 펌 패턴 번역이 우리 문법 안에 있는가(모방 복제 아님) — advisory.

## 4. 실행 게이트 — 어디서나 열리고 다시 보인다

```bash
python3 <base>/scripts/build_deck.py <작업 폴더>                              # 조립
python3 <base>/scripts/check_deck.py <결과.html> --sheets <작업 폴더>/qa     # 구조·대비·렌더·외부 자원
python3 consulting-deck/checks/check_consulting.py <작업 폴더>               # 컨설팅 게이트
python3 consulting-deck/charts/regen.py --check <작업 폴더>                  # 차트 재생성 계약
cd <base> && EDU_DECK_TEST_DECK=<실덱경로> python3 -m unittest discover -s dev -p 'test_*py'   # 전체 회귀
```

- 오프라인 재생: 결과 파일 하나를 끊어진 환경에서 열어 모션·단계가 동작하는가(외부 리소스 0은 check_deck이 검사).
- 모션: 단계 순서(주장→증거→해석→출처)·재방문(뒤로 갔다 올 때 상태)·reduced-motion·인쇄·정적 스크린샷.
- 기존 교육 덱 회귀: unittest 전체 + demo/si/pack regen이 무영향인지(공유 자산을 건드리지 않았다면 기본 무영향 — 확인으로 입증).

## 5. 자동 검사와 품질 승인은 별개다

- 자동 검사 통과 = 납품 **가능 조건**이지 좋은 컨설팅 덱이 아니다. 보고할 때 두 축을 나눠 적는다:
  - **자동**: 각 검사 명령과 결과(PASS/FAIL/NOT_RUN+이유) 한 줄씩.
  - **품질(사람 판단)**: 논리(제목 연쇄 읽힘·비약 없음)·데이터(표기 완전)·시각(위계·캡처 확인)·실행(모션·재방문) 각각 결론 한 줄 + 근거.
- 검사를 통과시키려고 검사 스크립트·기준을 고치지 않는다. 게이트 자체의 결함은 별도 보고 후 수정한다.

## 5-b. 심미 게이트 — 시각 판단 에이전트의 독립 검수 (2026-11-10 신설)

- **누가**: 저작 에이전트가 아니라 시각 판단 기능이 있는 에이전트(이 환경: agy/gemini-4-argon).
  절차·질문표·호출 규칙은 `references/design-review.md`.
- **무엇을**: 캡처 전 장(최종 상태)을 7관점으로 — 위계(3초 룰)·레이아웃 반복·타이포 리듬·
  차트 시사점·공간 활용·정체성(AI 범용 스타일 아닌가)·모션 목적성.
- **판정**: 심미 치명(메시지 불가시·정체성 부재·차트 무시사점)은 방향 수립 전 납품 중단.
  권고는 다음 패스, 취향은 기록만. 기술 결함(겹침·대비)은 심미와 분리해 코드 수정 의무.
- **증거**: 진단 보고서 + (개선 시) 전후 비교 캡처. 자동 검사 RESULT 줄을 심미 증거로 쓰지 않는다.

## 6. 인수 루브릭 — 최종 승인 질문 (1~5점)

| 차원 | 5점의 모습 |
|---|---|
| 의사결정 명료성 | 결정 질문·권고·요청이 명확하고 답할 수 있다 |
| 스토리라인 | 제목 연쇄가 저절로 읽히고 Exec Summary가 결론을 요약한다 |
| 증거 | 모든 수치가 원장으로 거슬러 올라가고 구분 표기가 완전하다 |
| 시각 위계 | 초점이 하나씩이고 차트가 주장을 지지하는 방향으로 읽힌다 |
| 컨설팅 크래프트 | 주장-근거-권고의 리듬, 전환 수사, 행동 마감이 살아 있다 |
| 일관성 | 색·골격·용어·단위가 덱 전체에서 같다 |
| 접근성·검증 가능성 | DOM 텍스트·대체 텍스트·재생성 계약으로 누구나 검증할 수 있다 |
| 수정 준비성 | 모델·원장·조각이 분리돼 있어 수치 수정이 한 곳에서 끝난다 |

납품 기준: blocker 0 + 자동 검사 전 PASS + 루브릭 전 차원 4점 이상. 미달 차원은 보고에 남기고 기준을 낮추지 않는다.
