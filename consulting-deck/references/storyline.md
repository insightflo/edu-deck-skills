> **소유 영역**: 컨설팅 덱의 서사 — 저작 형태 판별, 문제 정의, 이슈 트리, 통치 사상, 서사 뼈대, 주장형 제목, Exec Summary. 배치·차트·근거 형식은 각자의 문서가 소유한다.
> **로드 시점**: 작업 순서 1단계(형태 판별)와 3단계(스토리라인 설계), 그리고 장 제목을 다듬을 때.

# 컨설팅 스토리라인 (storyline)

## 1. 저작 형태를 먼저 고른다 — 두 경로는 다른 도구다

| | 문제해결형 | 자료종합형 |
|---|---|---|
| 과제의 본질 | 결정이 걸렸다(진입·투자·전환·승인) | 자료를 충실하게 종합해 보여준다(동향·연간 리뷰·브리핑) |
| 핵심 도구 | 문제 정의 → 이슈 트리 → 가설 → 반증 → 권고 | 주제 분해 → 요약 계층 → 함의(2절 이하로 축소) |
| 서사 뼈대 | SCQA 또는 진단–선택–동원 | What–So what–Now what |
| 금지 | — | **가설 트리 강요** — 결정이 없는데 가설을 세우면 내용이 늘어진다 |

판별 질문: "이 덱을 다 읽은 독자가 무엇을 하게 되나?" 결정/승인/착수면 문제해결형, 이해/공유면 자료종합형. 혼합 덱(전반 동향 + 후반 권고)은 장 그룹을 나눠 그룹별로 적용한다.

## 2. 문제 정의 — 문제해결형의 출발점

- **의사결정 질문 1개**: "X 세그먼트에 진입해야 하는가? 조건이 있다면 무엇인가?"처럼 예/아니오 또는 선택지로 답할 수 있는 문장.
- 정의에 남길 것: 결정 주체 · 결정 기한 · 범위 안/밖(다루지 않을 것) · 제약(예산·조직·규제) · 성공 기준 · 지금 모르는 것.
- 모호한 요청("시장을 분석해줘")은 brief 단계에서 의사결정 질문으로 바꾼다. 바꿀 수 없으면 자료종합형이다.

## 3. 이슈 트리 — 의사결정 질문을 증명 가능한 조각으로 나눈다

- 2~3단계까지만. MECE는 도식이 아니라 **품질 테스트**다 — 가지마다 네 가지를 묻는다:
  1. 이 가지의 답이 바뀌면 결정이 바뀌는가?
  2. 증명 가능한가(수치·사례·비교로)?
  3. 다른 가지와 겹치지 않는가?
  4. 결정에 필요한 인자가 빠져 있지 않은가?
- 가지는 화면의 장과 대응시킨다. 트리에 없는 장은 덱에도 없는 게 정상이고, 필요해지면 트리를 먼저 고친다.

## 4. 통치 사상(Governing Thought) — 전체 주장 한 문장

덱 전체를 요약하는 주장문. 네 요건을 다 충족해야 한다:

1. **반박 가능할 만큼 구체적** — 수치·조건·기한이 들어간다("비용 구조를 바꿔야 한다" ✗ → "클라우드 이관로 라이선스·운영비에서 연 120억을 줄일 수 있다" ✓)
2. **증거가 뒷받침한다** — 덱의 장들이 이 문장을 지지하는 순서로 놓인다
3. **의사결정과 연결된다** — 결정 주체가 이 문장 때문에 움직인다
4. **외울 수 있을 만큼 짧다** — 회의실을 나서며 한 문장으로 반복할 수 있다

Exec Summary의 첫 문장이 곧 통치 사상이다. 두 문장이 다르면 둘 중 하나가 틀렸다.

## 5. 서사 뼈대 — 덱의 유형에 따라 하나를 고른다

| 뼈대 | 구성 | 맞는 덱 |
|---|---|---|
| **SCQA** | 상황(S) → 복잡화(C: 무엇이 꼬였나) → 질문(Q) → 답(A) | 권고·변화 제안. 경영진이 상황을 알고 있을 때 강하다 |
| **What–So what–Now what** | 사실 → 함의 → 할 일 | 조사 요약·자료종합형 |
| **진단–선택–동원** | 어디가 아픈가 → 무엇을 고르나 → 어떻게 움직이나 | 전략·전환. 문제해결형의 기본값 |
| **가설–증거–함의** | 가설(명시 라벨) → 확보된 증거 → 그래서 무엇 | 증거가 아직 불완전할 때. 가설임을 숨기지 않는다 |

뼈대는 장 그룹의 순서를 정한다. 장마다 하나의 역할만 갖는다(§7 페이지 역할).

## 6. 주장형 제목(액션 타이틀) — 제목이 곧 논증

- 제목은 **결론의 문장**이다. 주어와 함의를 담는다: "AI 도입 현황" ✗ → "AI 도입은 확산 중이나 대부분 조직은 파일럿에 머물러 있다" ✓
- 길이는 한국어 15~35자 안팎. 한 줄로 끝나고, 부제(eyebrow)에 단위·기간을 나눠 실는다.
- **전환 수사로 장력을 만든다**: "…개선했다" → 다음 장 "…그러나 분포는 10년 최저다". 'A에서 B로'(전환 서술), '그러나'(반전) 쌍은 컨설팅 덱 고유의 리듬 장치다.
- 토픽 명사형 제목은 부록·섹션 구분 장에만 허용된다.

## 7. 페이지 역할 — 장마다 하나

`orient`(방향 제시) · `assert`(주장) · `prove`(증명·차트) · `compare`(비교) · `explain`(메커니즘 설명) · `decide`(결정) · `mobilize`(동원·실행) · `reference`(부록·원본 전시).

- 스토리라인 표의 각 장에 역할을 적는다. 한 장에 역할이 둘이면 두 장으로 나눈다.
- prove 장과 assert·compare 장을 교대로 놓는다(증명 연속 3장 금지 — 배치 다양성 규칙과 같은 맥락, `consulting-layouts.md`).

## 8. 수평 논리 테스트 — 제목만 읽어 논지가 완성되는가

- 장 제목을 순서대로 소리 내어 읽는다. 짧은 경영 메모처럼 읽히면 통과다.
- 걸리는 것: 인접한 두 장의 결론이 같은 테이크어웨이라면 하나로 합친다 · 진단 없이 행동이 나오면(비약) 중간 증명 장이 빠진 것이다 · 부록 이야기가 본문 흐름에 끼어들면 reference로 보낸다.
- 세로 논리: 각 장은 (주장형 제목 1) + (그 주장을 지지하는 증거 구조 1) + (해석 주석) + (출처·방법론)로 완성된다. 비교가 명시적 임무가 아니면 경쟁사 차트를 여러 개 늘어놓지 않는다.

## 9. Exec Summary — 결론 요약, 주제 요약이 아니다

덱의 첫 장(표지 다음). 구성 순서:

1. **통치 사상** 1문장(§4)
2. 지지 인사이트 **3~5개** — 각각 뒷장의 주장형 제목과 하나씩 대응
3. 권고 행동 **2~4개** — 마지막 장의 권고와 일치
4. 핵심 정량 증거 1~3개(수치+기준)
5. 불확실성·가정 한 줄(있을 때만)

- **본문을 다 쓴 뒤에 마지막으로 쓴다.** 본문 주장을 고치면 Exec Summary도 고친다(check_consulting이 문장 대응을 검사한다).
- 배치는 `consulting-layouts.md` 유형 2(Exec Summary), At-a-Glance 3불릿 형식(주장+수치).

## 10. 기본 시퀀스 — 출발점 재료 (요청에 맞게 조정)

| 문제해결형 11~12장 | 자료종합형 9~11장 |
|---|---|
| 1 표지 | 1 표지 |
| 2 Exec Summary | 2 Exec Summary(핵심 요약 3불릿) |
| 3 SCQA/문제 정의 | 3 주제 구조(무엇을 다루나) |
| 4 이슈 트리/가설 | 4~8 핵심 주제 장(주장+증거 교대) |
| 5~9 가지별 증명 장(차트·비교·벤치마크) | 9 함의(So what) |
| 10 전략 대안·트레이드오프 | 10 다음 단계(Now what) |
| 11 권고·로드맵 | 11 부록 |
| 12 위험·의사결정 요청·부록 | |

장 수는 규칙이 아니라 참고값이다. 요구가 정하면 요구가 이긴다.

## 11. 편집 규칙 — 초안을 다듬을 때

- 청중이 이미 아는 배경은 지운다. Exec Summary의 분량은 결론이 채운다.
- 형용사를 증거로 바꾼다: "급격한 증가" → "전년 대비 44% 증가".
- 인용·수치·사례·출처를 만들어내지 않는다. 없으면 가설 라벨을 붙이거나 뺀다(evidence.md).
- 내부 계획 언어("추후 논의", "WIP", 담당자 지시문)가 화면에 남지 않게 한다.
