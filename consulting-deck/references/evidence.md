> **소유 영역**: 근거 원장 evidence.json의 형식, 증거 유형과 신선도, 가정/사실 구분, 가상 데이터 표기, 계산 검증. 출처 목록·복제 경계는 `reference-sources.md`가, 차트 모델 문법은 `charts/schema.md`가 소유한다.
> **로드 시점**: 작업 순서 2단계(조사)에서 원장을 열 때, 4단계(차트)에서 수치를 모델에 넣을 때, 검사 결과를 해석할 때.

# 근거 관리 (evidence)

## 1. 대원칙

- 근거 없는 수치를 화면에 쓰지 않는다. 근거를 못 찾으면 **가상 데이터로 만들고 표기한다** — 지어내고 표기하지 않는 것은 둘 다 금지다.
- 화면의 모든 숫자는 원장 `evidence.json`의 claim 하나로 거슬러 올라간다. 제목·본문·차트·Exec Summary 어디에 있어도 같다.
- 근거가 약할수록 문장을 약하게 쓴다. 가설은 가설이라고, 전망은 전망이라고 화면에 남긴다.

## 2. evidence.json 구조

작업 폴더 루트에 둔다. `check_consulting.py`가 이 파일을 덱과 대조한다.

```json
{
  "sources": [
    {
      "source_id": "S01",
      "kind": "report | article | internal | interview | calculation",
      "title": "Global Private Equity Report 2026",
      "publisher": "Bain & Company",
      "locator": "URL 또는 문서 경로+페이지",
      "published": "2026-03",
      "asOf": "2025-12-31",
      "accessed": "2026-11-10",
      "freshness": "current | aging | stale"
    }
  ],
  "claims": [
    {
      "claim_id": "C01",
      "slide": "05-비용구조",
      "statement": "라이선스 비용이 3년간 연 11%씩 증가했다",
      "value": "11.2% (CAGR FY22–FY25)",
      "source_id": "S01 p.23",
      "original": "FY22 412억 → FY25 566억",
      "method": "CAGR = (566/412)^(1/3)−1",
      "kind": "fact | calculated | estimate | projection | synthetic",
      "assumptions": [],
      "contrary": [],
      "uncertainty": ""
    }
  ]
}
```

| 필드 | 규칙 |
|---|---|
| `source_id` | 덱 전체에서 유일. S01, S02… |
| `locator` | URL 또는 문서+페이지. "웹 검색" 같은 총칭은 안 된다 |
| `freshness` | current(최신 주기)·aging(1~2주기 전)·stale(그 이상). stale을 쓰면 화면에 기준일을 반드시 표기 |
| `claim_id` | C01… 차트 모델·스토리라인 표에서 인용 |
| `original` + `method` | 계산값(calculated)은 원본 값과 계산식을 둘 다 남긴다 |
| `kind` | §4 구분. synthetic은 §5 표기가 따른다 |
| `contrary` | 반대 근거나 반례. 찾았으면 적는다 — 없다는 건 안 찾았다는 뜻임을 안다 |
| `assumptions` | 추정·전망의 가정. 화면 표기와 1:1 대응 |

## 3. 증거 유형 — 다섯 가지를 섞지 않는다

| 유형 | 정의 | 화면 취급 |
|---|---|---|
| 사실(fact) | 출처에 있는 원문 수치·문장 | 출처 라벨과 함께 |
| 계산(calculated) | 사실에서 연산한 값 | 원본 값·식을 원장에, 화면에는 값+출처 |
| 추정(estimate) | 가정 위의 합리적 값 | "추정" 표기 + 주요 가정 |
| 전망(projection) | 미래 값 | "전망" 표기 + 기간·시나리오 |
| 가설(hypothesis) | 아직 증명 안 된 해석 | "가설" 라벨. 사실 문장 사이에 섞지 않는다 |

인용(quotation)은 사실의 하위 — 짧게 쓰고 따옴표와 출처를 붙인다. 해석(interpretation)은 원장 없이 저자의 판단으로 쓸 수 있되, 수치·출처가 뒷받침하는 해석만 화면에 남긴다.

## 4. 가정/사실 구분 표기 — 화면 규칙

- 슬라이드 본문에서 전망·추정 수치 뒤에는 "(전망)" "(추정)"을 붙이거나 eyebrow에 시나리오를 적는다.
- 실적과 전망이 같은 차트에 있으면 계열·음영·라벨로 구분하고 방법론 노트에 기준 시점을 적는다.
- "업계 평균 대비" 같은 비교는 기준(무엇의 평균, 표본, 기간)을 방법론 노트에 남긴다.
- 표본이 있는 조사 수치는 표본 규모를 주장 가까이에 놓는다("응답 기업 2,400사 중 74%").

## 5. 가상 데이터 표기 — 계약

- 근거 없이 만든 수치는 전부 synthetic이다. 데모·예시 덱의 수치도 마찬가지다.
- **차트**: 모델의 `source.synthetic: true` → 생성기가 출처 블록에 "가상 데이터"(`s-syn`)를 강제 표기한다. `false`로 두고 근거를 못 대면 검증 FAIL이다.
- **글자·표**: synthetic claim을 화면에 싣는 장의 출처 라인에 "가상 데이터"를 넣고, evidence.json의 해당 claim `kind`를 `synthetic`으로 둔다.
- 가상 수치에 그럴듯한 출처("업계 보고서")를 붙이지 않는다. 출처가 없다는 사실이 출처다.

## 6. 계산 검증 — 조정 체크리스트

납품 전에 아래를 확인한다. 앞의 여섯은 `check_consulting.py`·`chart_gen.mjs`가 자동 검사하고, 나머지는 사람이 검토한다.

1. 구성비 합계 = 총합(100% 또는 명시 총계)
2. 워터폴: 시작 + 드라이버 합 = 끝(expectTotal)
3. 차트 라벨 ↔ 눈에 보이는 숫자 일치
4. 제목의 주장 ↔ 차트가 실제로 보여주는 것 일치
5. 화면 수치 ↔ evidence.json 원장 값 일치(반올림 규칙 통일)
6. Exec Summary 수치 ↔ 본문 수치 일치
7. 단위·통화·기간·분모가 장마다 같다(%의 분모가 몇인지 명시)
8. 증감률·CAGR·지수 계산의 기준점이 맞다
9. 반올림: 장 안에서는 같은 자릿수, 합계는 반올림 전 값 기준
10. 인용문이 원문과 글자 순서까지 같다
11. stale 출처의 기준일이 화면에 남아 있다
12. 반대 증거(contrary)를 확인했고, 덱이 무시하지 않는다(한계로 명시하거나 반박한다)

## 7. 출처 라인·방법론 노트 — 화면 형식

- 출처는 장 하단 출처 블록(`c-src`)에: `Source: 발행처 「제목」(연도) · 기준 2025-12`. 내부 자료는 `Source: 사내 ○○ 시스템 추출 (2026-11-10)`.
- 방법론·한계는 한 줄로(`c-note`): 정의·제외 항목·환율·표본. "기타 제외", "환율 1,380원 적용", "응답 412사 중 유효 398사".
- 출처가 여럿이면 `·`로 잇는다. 분석 해석이 섞이면 "○○ 분석"을 병기한다.
- 발표 노트(aside.notes)에도 각 수치의 근거를 한 줄 남겨 질문에 답할 수 있게 한다.
